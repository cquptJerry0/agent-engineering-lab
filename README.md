# Agent Engineering Lab

这个仓库用于建立一套完整、现代、可迁移的 Agent 开发学习体系。

目标不是追完最多课程，也不是记住最多框架 API，而是用尽可能短的路径建立能够解释、实现、评测和演进真实 Agent 系统的工程能力。

## 从这里开始

仓库只有一个知识主干：

> [学习总纲](docs/学习总纲.md)

第一次进入仓库时，按下面的顺序阅读：

1. 阅读[学习总纲](docs/学习总纲.md)开头的全景图和推荐顺序，理解整个体系。
2. 阅读[知识模块](docs/知识模块/README.md)，理解每块内容为什么同时有理解版和题目版。
3. 进入[课程大纲](docs/课程/README.md)，按照 9 章 30 课在当前会话中推进。
4. 阅读[学习方法](docs/学习方法.md)，了解每个知识点如何形成学习闭环。
5. 开始某个章节后，在[学习进度](docs/学习进度.md)记录理解、实验和复核证据。
6. 需要选择资料时查阅[资料与证据](docs/资料与证据.md)。
7. 想了解尚未稳定的新方向时查阅[前沿雷达](docs/前沿雷达.md)。

## 学习目标

1. 快速掌握 Agent 开发的核心原理，不从框架 API 和工程面试题开始。
2. 建立能够串联 Loop(执行循环)、Graph(状态图运行时)、Harness(智能体运行支撑环境)和持续改进闭环的统一心智。
3. 每个主干知识点至少能解释机制、完成最小实验、识别失败边界。
4. 用贯穿项目连接知识，但不让单个项目决定学习范围。
5. 通过 Trace(完整执行轨迹)、Eval(系统化评测)和回归测试证明能力，而不是把“看完资料”当成掌握。

## 核心方法

```text
完整知识总纲
    +
最小机制实验
    +
失败场景分析
    +
贯穿项目
    +
评测与复核
```

项目负责串联和验证，知识总纲负责防止遗漏，评测负责防止自我感觉良好。

正式学习一个模块时采用双轨内容：

```text
理解版：问题 → 推导 → 机制 → 案例 → 失败 → 实验 → 边界
题目版：核心判断 → 30 秒回答 → 3 分钟回答 → 追问 → 证据
```

这套结构复用了旧学习仓库中“推导式理解 + 满分题解 + 输出训练”的成熟心法，但不会复制旧技术内容本身。

## 总体心智

```text
理解模型
   ↓
构造 Agent 执行内核
   ↓
管理上下文、状态、记忆、工具与知识
   ↓
处理复杂任务和长期任务
   ↓
构造完整 Harness
   ↓
通过 Trace 与 Eval 持续改进
   ↓
进入可靠、安全、可治理的生产环境
```

`Loop`是每次任务的行动内核，`Graph`负责显式表达复杂控制流和可恢复执行，`Harness`决定模型能看到什么、能做什么以及如何得到反馈，持续改进闭环负责根据真实执行证据优化整个系统。它们是包含和协作关系，不是新概念淘汰旧概念。

## 英文术语规则

- Agent、API、RAG、MCP 等已经广泛使用的缩写可以直接保留。
- 较难但必须保留的英文术语，第一次出现时使用`英文(精简通俗注释)`。
- 同一个术语在后文不反复解释，避免影响阅读。
- 能用准确中文表达时优先使用中文，不为了显得专业堆英文。

## 当前阶段

当前阶段先稳定知识总纲、资料证据和学习方法，暂不提前锁死周计划、主框架和最终项目。

后续需要共同决定：

- 第一轮学习的时间预算。
- 主实验语言。
- 贯穿项目的业务目标与验收标准。
- 主框架与对照框架。
- 阶段测验、复习频率和最终评测集。
