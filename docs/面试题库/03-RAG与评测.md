# RAG 与评测面试题

## 1. 使用边界

这份题库覆盖 RAG(Retrieval-Augmented Generation，检索增强生成)的索引、召回、排序、上下文构建、回答生成和评测闭环。重点是解释每个机制解决的失败，而不是背固定参数。

## 2. 架构与适用边界

### RAG-ARCH-001：请画出一个完整 RAG 系统从数据进入到回答返回的链路。

常见追问：

- 采集、解析、切分、索引、召回、排序、上下文组装和生成分别输入输出什么？
- 离线链路和在线链路如何拆分？
- 每一层应该记录哪些可观测信息？

主干定位：[Knowledge、Search 与 RAG](../学习总纲.md#73-knowledgesearch-与-rag)

来源：S1、S6、S11、S12

### RAG-ARCH-002：哪些问题适合使用 RAG，哪些问题更适合微调、工具查询或长上下文？

常见追问：

- 知识新鲜度、私有数据、引用要求和任务格式如何影响选择？
- 数据规模很小时是否还需要向量数据库？
- RAG 与微调能否组合？

主干定位：[Knowledge、Search 与 RAG](../学习总纲.md#73-knowledgesearch-与-rag)

来源：S7、S11

### RAG-ARCH-003：长上下文模型已经能放入大量文档，为什么还需要检索？

常见追问：

- 成本、延迟、注意力稀释和权限过滤分别有什么影响？
- 全量塞入与检索后的上下文如何做对照实验？
- 什么规模和任务下，直接长上下文反而更简单？

主干定位：[Knowledge、Search 与 RAG](../学习总纲.md#73-knowledgesearch-与-rag)

来源：S6、S11、S12

- 如何根据失败样本选择优化层，而不是同时改所有参数？

常见追问：

- 回答更长是否等于效果更好？
- 如何避免优化一个指标却伤害忠实度或拒答能力？
