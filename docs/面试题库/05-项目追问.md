# AI Agent 项目追问

## 1. 使用边界

这份题库用于检查项目是否真实、取舍是否清楚、效果是否有证据。回答时应优先使用自己项目中的请求、数据、故障、指标和代码，避免只复述行业通用架构。

## 2. 项目目标与真实性

### PROJECT-VALUE-001：你为什么做这个 Agent 项目，它解决了谁的什么问题？

常见追问：

- 原流程的时间、成本、错误或体验问题是什么？
- 真实用户是谁，使用频率和任务规模是多少？
- 为什么这个问题值得使用 AI？

主干定位：[学习目标](../学习总纲.md#2-学习目标)

来源：S8、S10

### PROJECT-VALUE-002：这个项目真的需要 Agent 吗？

常见追问：

- 普通搜索、规则、工作流或单次模型调用能否完成？
- 哪一部分需要动态决策、工具使用或环境反馈？
- Agent 增加的成本和不确定性是否值得？

主干定位：[Agent Loop 与决策](../学习总纲.md#61-agent-loop-与决策)

来源：S8、S10

### PROJECT-VALUE-003：项目当前是演示、内部试用还是生产系统？

常见追问：

- 有多少真实用户、请求和成功任务？
- 哪些能力已经上线，哪些仍是规划？
- 演示链路与生产链路有什么差异？

主干定位：[完整性与维护原则](../学习总纲.md#14-完整性与维护原则)

来源：S8、S10

## 3. 架构与取舍

### PROJECT-ARCH-001：请用一张图讲清项目的端到端调用链。

常见追问：

- 用户请求经过前端、服务端、模型、检索、工具和存储的顺序是什么？
- 状态和身份在哪些层传递？
- 最可能失败和最难观测的位置在哪里？

主干定位：[全景心智模型](../学习总纲.md#3-全景心智模型)

来源：S8、S10

### PROJECT-ARCH-002：你为什么选择当前模型、框架、向量库和部署方式？

常见追问：

- 当时比较过哪些替代方案？
- 决策依据是能力、成本、延迟、生态还是团队约束？
- 如果移除框架，底层机制是否仍能讲清？

主干定位：[完整性与维护原则](../学习总纲.md#14-完整性与维护原则)

来源：S8、S10

### PROJECT-ARCH-003：项目中的状态、上下文和长期记忆分别保存在哪里？

常见追问：

- 哪个存储是真相来源？
- 页面刷新、服务重启和任务恢复后怎样重建状态？
- 数据过期、冲突和用户删除如何处理？

主干定位：[上下文、状态与记忆](../学习总纲.md#71-contextstate-与-memory)

来源：S3、S8

### PROJECT-ARCH-004：如果不用你当前的 Agent 框架，你会如何自己实现最小版本？

常见追问：

- 最小 Loop、工具注册、上下文组装和终止条件如何写？
- 框架替你承担了哪些工程能力？
- 哪些框架能力在你的项目里其实没有用到？

主干定位：[Agent Loop 与决策](../学习总纲.md#61-agent-loop-与决策)

来源：S8

## 4. 难点、故障与调试

### PROJECT-DEBUG-001：项目中最难定位的一次故障是什么？

常见追问：

- 用户表现、真实根因和误导性现象分别是什么？
- 你增加了什么日志、实验或最小复现？
- 修复后如何证明不再发生？

主干定位：[Trace 与 Eval](../学习总纲.md#101-trace-与-eval)

来源：S8、S9、S10

### PROJECT-DEBUG-002：讲一个模型输出正确，但系统最终行为错误的案例。

常见追问：

- 错误发生在协议解析、工具参数、权限、状态还是界面？
- 当时为什么没有被测试发现？
- 后续增加了哪一层防线？

主干定位：[Harness Engineering](../学习总纲.md#91-harness-engineering)

来源：S8、S10

### PROJECT-DEBUG-003：讲一个你最初以为是模型问题，最后发现是工程问题的案例。

常见追问：

- 如何排除 Prompt 和模型随机性？
- 是否检查过数据版本、缓存、并发、超时和序列化？
- 这个故障怎样改变了你的可观测设计？

主干定位：[Trace 与 Eval](../学习总纲.md#101-trace-与-eval)

来源：S8、S9

### PROJECT-DEBUG-004：你的系统如何处理生成失败、工具失败和整条任务失败？

常见追问：

- 哪些错误自动重试，哪些需要用户介入？
- 用户能否从失败步骤继续？
- 是否存在重复副作用或状态不一致？

主干定位：[可靠性、安全与治理](../学习总纲.md#111-可靠性安全与治理)

来源：S4、S8、S14

## 5. 数据、评测与效果证明

### PROJECT-EVAL-001：你如何证明项目效果比基线更好？

常见追问：

- 基线是人工流程、规则、搜索、旧模型还是无 RAG 版本？
- 离线指标、线上指标和业务指标分别是什么？
- 改进是否通过同一数据集和同一约束比较？

主干定位：[Trace 与 Eval](../学习总纲.md#101-trace-与-eval)

来源：S3、S8、S10

### PROJECT-EVAL-002：你的评测数据集从哪里来？

常见追问：

- 真实请求、专家构造和模型生成各占多少？
- 是否覆盖失败、边界、攻击和不可回答样本？
- 如何防止开发过程对固定评测集过拟合？

主干定位：[Trace 与 Eval](../学习总纲.md#101-trace-与-eval)

来源：S3、S10

### PROJECT-EVAL-003：如果评测使用 LLM-as-a-Judge(用模型充当评审)，你如何证明评审可信？

常见追问：

- 是否与人工标注做过一致性检查？
- 裁判模型知道候选系统身份吗？
- 位置、长度和文风偏差如何控制？

主干定位：[Trace 与 Eval](../学习总纲.md#101-trace-与-eval)

来源：S3、S10

### PROJECT-EVAL-004：项目上线后，哪些指标真正影响了下一轮迭代？

常见追问：

- 失败轨迹如何进入样本库？
- 哪次改动因为线上证据被回滚？
- 如何区分用户不满意来自模型质量还是产品体验？

主干定位：[Loop Engineering 与持续改进](../学习总纲.md#102-loop-engineering-与持续改进)

来源：S8、S10
