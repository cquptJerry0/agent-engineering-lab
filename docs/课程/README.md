# 动态课程

## 1. 定位

这个目录不保存预先排好的固定课表，只保存根据当前学习状态实际生成的课程单元。

课程单元简称 `CU(Course Unit，课程单元)`。每个 CU 是学习总纲在某一时刻的动态视图：

```text
稳定知识总纲
    +
当前学习进度
    +
最近暴露的薄弱点
    +
当前项目或面试目标
    ↓
动态选择一组存在因果关系的知识点
    ↓
生成一个实际 CU
```

课程数量、知识分组和学习顺序都不是长期事实。它们会随着掌握证据、遗忘情况、项目需求和面试目标变化。

## 2. 唯一输入

动态选课只读取四类信息：

| 输入 | 负责回答的问题 |
|---|---|
| [学习总纲](../学习总纲.md) | 完整知识边界、依赖关系和掌握标准是什么 |
| [学习进度](../学习进度.md) | 已经掌握什么、薄弱点在哪里、有什么证据 |
| [面试题库](../面试题库/README.md) | 真实面试会怎样提问和追问 |
| [资料索引](../资料索引.md) | 机制结论依据什么，哪些方向仍待验证 |

课程不能反向修改知识边界。学习中发现知识缺口时，先核实证据，再更新学习总纲。

## 3. 动态选课

每次开始或继续学习时，先执行下面的选择过程：

```text
确定本轮目标
  ↓
从进度中找未掌握、曾答错或需要复核的知识点
  ↓
检查总纲中的前置依赖
  ↓
寻找能够共享同一个问题、状态和案例的相邻知识点
  ↓
编译成一个 CU
```

优先级从高到低：

1. 当前项目或面试马上需要，但已有理解不足的内容。
2. 阻塞多个后续知识点的基础机制。
3. 曾经答错、实验失败或只能背诵的内容。
4. 长时间未复核、存在遗忘风险的内容。
5. 尚未开始但暂时不阻塞后续学习的内容。

不要因为知识点在总纲中相邻就强行合并。只有满足下面条件时才进入同一个 CU：

- 共同回答一个完整问题。
- 前一个机制留下的问题会自然引出下一个机制。
- 能使用同一个案例和连续状态。
- 能形成一条端到端 Trace 或时间线。
- 一次学习可以完成理解、实验设计和复述。

## 4. 双轨产物

每个 CU 使用一个目录保存两条严格分离的学习轨道：

```text
docs/课程/CU-序号-主题/
├── 推导式理解.md
└── 面试训练.md
```

### 推导式理解

第一轨负责真正学懂。它必须使用一个贯穿案例，让同一个系统版本持续演进：

```text
已有能力
  ↓
在真实案例中暴露问题
  ↓
解释为什么现有机制解决不了
  ↓
引入新机制
  ↓
更新系统状态
  ↓
留下下一阶段问题
```

知识点不是并排列举。删除中间机制后，后续推导应该出现明显断裂。

### 面试训练

第二轨只在推导式理解稳定后生成。它从第一轨抽取题目，按真实面试方式组织：

```text
完整题目
  ↓
一句话核心判断
  ↓
启发式思考
  ↓
30 秒回答
  ↓
完整回答
  ↓
连续追问
  ↓
实验或项目证据
```

面试训练不能另造知识结论，必须回链推导式理解中的章节、图和实验。

## 6. 状态更新

生成课程文档不代表已经掌握。

```text
课程生成
  → 状态仍为未开始

完成讲解和独立复述
  → 已理解

完成正常与失败实验
  → 已实验

进入综合项目并通过端到端验证
  → 已整合

间隔复习和陌生案例迁移通过
  → 已复核
```

每次 CU 完成后更新[学习进度](../学习进度.md)，再重新计算下一 CU，不提前承诺固定课数。
