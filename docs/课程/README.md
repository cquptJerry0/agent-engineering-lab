# Agent 开发课程大纲

## 1. 课程定位

这份文档负责把[学习总纲](../学习总纲.md)转换成可以在当前会话中逐节完成的课程。

两份文档的职责不同：

| 文档 | 负责回答的问题 |
|---|---|
| [学习总纲](../学习总纲.md) | Agent 开发完整知识边界是什么 |
| [知识模块](../知识模块/README.md) | 每块知识的理解版和题目版正文是什么 |
| 本课程大纲 | 总共讲多少课、每课讲什么、如何验收 |
| [课程模板](课程模板.md) | 每节课必须怎样讲，才能保证高 ROI |
| [学习进度](../学习进度.md) | 哪些知识已经形成掌握证据 |
| [面试题库](../面试题库/README.md) | 面试会怎样提问和连续追问 |

课程不能修改知识主干，也不长期保存另一套知识正文。课程中形成的稳定机制结论回写对应理解版，面试答案回写对应题目版。临时出现的新技术先进入[前沿雷达](../前沿雷达.md)，经过证据核实后再决定是否调整课程。

## 2. 课程规模

```text
1 节导学
  +
9 章正式课程
  +
29 节正文课
  =
总计 30 节课
```

一节课不等于一个知识点。课程围绕一个完整工程问题，串联总纲中强相关的多个知识点。

课程采用产出驱动，不用固定时长判断完成。每节课至少产出：

1. 一张能够脱离正文独立解释机制的 ASCII 图(纯文本结构图)。
2. 一个包含真实输入、状态、环境和输出的具体案例。
3. 一个最小正常实验和一个失败实验。
4. 一份可直接用于面试的核心判断、完整答案和追问树。
5. 一条可以写入[学习进度](../学习进度.md)的掌握证据。

## 3. 高 ROI 原则

### 先思考，再讲答案

每节课先给一个需要预测、取舍或排障的问题。回答正确不是前提，暴露当前心智才是目的。

### 先机制，再看框架

先看真实协议、状态和控制流，再研究代表性系统如何封装。每节课只选择一两个真正有对照价值的框架或产品，不围绕品牌组织知识。

### 每课必须有真实案例

案例不能只有“假设有一个 Agent”。它必须给出：

- 用户目标。
- 模型可见上下文。
- 可用工具和权限。
- 关键状态。
- 真实输出或副作用。
- 成功标准和失败表现。

### 每课必须主动制造失败

正常 Demo 只能证明链路偶然跑通。课程会主动制造参数错误、上下文污染、状态丢失、重复副作用、检索失败、越权调用和评测过拟合。

### 以面试答辩为收束

每节课最后形成：

```text
一句话核心判断
  ↓
30 秒直接回答
  ↓
3 分钟完整答案
  ↓
ASCII 机制图
  ↓
连续追问与反问
  ↓
项目或实验事实
```

目标不是背标准答案，而是能够用机制、边界和真实证据接住追问。

## 4. 教学案例

课程以`企业研发任务 Agent`作为主要教学母案例：

```text
用户提交研发任务
  ↓
Agent 读取仓库、文档和运行日志
  ↓
检索相关知识与历史经验
  ↓
制定计划并调用工具执行
  ↓
运行测试或回读外部系统
  ↓
高风险动作等待人工审批
  ↓
记录 Trace、评测结果和失败经验
```

母案例只负责保持课程连贯，不提前锁死最终贯穿项目。RAG、客服、Deep Research(深度研究智能体)和 Coding Agent(编码智能体)会作为对照案例出现。

## 7. 导学

### 第 00 课：一条真实 Agent 请求究竟如何运行

- 核心思考：调用一次大模型、固定 Tool Calling(工具调用)和真正的 Agent Loop 到底差在哪里？
- 总纲主归属：全景心智模型、模型交互原语，以及 Agent Loop(执行循环)、Graph(状态图运行时)、Harness(智能体运行支撑环境)和 Eval(系统化评测)的位置关系。
- 具体案例：用户要求研发 Agent 定位一次发布失败；系统需要读取发布记录、搜索文档、分析日志并给出可验证结论。
- ASCII 图主题：普通模型调用、固定 Workflow(工作流)、Agent Loop、Graph 和 Harness 的包含关系。
- 最小实验：手工模拟一条包含模型请求、工具结果、状态更新和终止判断的 Trace。
- 失败实验：删除验证步骤，观察模型如何在没有真实证据时宣称任务完成。
- 面试目标：能够回答 `AGENT-LOOP-001`、`AGENT-RUNTIME-001`、`AGENT-HARNESS-001` 和 `PROJECT-ARCH-001`。
- 完成标准：不看资料画出完整链路，并准确说明控制权、状态和失败分别由谁处理。

## 8. 第一章：模型与真实 API

### 第 01 课：模型为什么聪明，又为什么不可靠

- 核心思考：同一个 Prompt 重复执行为什么可能得到不同结果？这算 Bug 吗？
- 总纲主归属：Token、Transformer 直觉、自回归生成、解码参数、对齐、幻觉和模型选型。
- 具体案例：研发 Agent 根据同一段模糊日志，两次选择了不同的故障原因和修复路径。
- ASCII 图主题：文本经过 Tokenizer、上下文和概率生成后形成输出的最小链路。
- 最小实验：重复调用同一问题，对比 Temperature、信息位置和上下文长度对结果的影响。
- 失败实验：在长上下文中加入冲突信息，观察模型引用了哪一条以及是否暴露不确定性。
- 面试目标：能够回答 `AGENT-MODEL-001`、`AGENT-MODEL-002` 和 `AGENT-MODEL-004`。
- 完成标准：能从生成机制解释非确定性、幻觉和上下文依赖，而不是只说“模型概率性很强”。

### 第 02 课：一次模型请求的真实数据结构

- 核心思考：聊天界面中的一条消息，为什么不能直接等同于模型 API 的一条消息？
- 总纲主归属：消息角色、请求响应、流式事件、Usage(用量统计)、Finish Reason(结束原因)、错误、超时和供应商差异。
- 具体案例：Agent 前端需要同时展示文本生成、工具准备、工具结果和用户取消。
- ASCII 图主题：客户端、Agent 服务、模型服务之间的请求和流式事件链。
- 最小实验：直接调用原生模型 API，打印完整请求、流事件、结束原因和 Token 用量。
- 失败实验：中途取消请求，并区分用户取消、网络中断、模型错误和服务端超时。
- 面试目标：能够回答 `AGENT-MODEL-001`、`FE-STREAM-001`、`FE-STREAM-003` 和 `FE-STREAM-004`。
- 完成标准：能根据一段原始响应判断模型是否正常结束，并设计不会串线的请求标识。

### 第 03 课：结构化输出与 Tool Calling 的真实协议

- 核心思考：模型返回了一段合法 JSON，为什么不等于已经完成工具调用？
- 总纲主归属：Structured Output(结构化输出)、Schema、Function Calling、工具参数和结果回填。
- 具体案例：Agent 需要先查询发布状态，再根据结果决定是否执行回滚。
- ASCII 图主题：模型生成工具请求、程序校验并执行、结果回填、模型继续决策的完整往返。
- 最小实验：实现一个查询工具和一个写工具，完整记录参数、执行结果和回填消息。
- 失败实验：制造非法字段、合法但越权的业务参数以及工具返回格式变化。
- 面试目标：能够回答 `AGENT-MODEL-003`、`AGENT-TOOL-001` 和 `AGENT-TOOL-003`。
- 完成标准：能解释结构化输出、Tool Calling、工具执行和业务成功是四个不同层次。

## 9. 第二章：Agent 执行内核

### 第 04 课：从零手写最小 Agent Loop

- 核心思考：为什么“模型可以调用工具”仍然不一定构成 Agent？
- 总纲主归属：观察、推理、行动、结果、验证、停止，以及 ReAct(边推理边行动)。
- 具体案例：Agent 在日志查询、服务状态和发布记录之间自主选择下一步。
- ASCII 图主题：一次循环中的观察、决策、行动、反馈和停止。
- 最小实验：不依赖 Agent 框架，手写支持多个工具和最大步数的执行循环。
- 失败实验：让工具持续返回无效结果，观察 Agent 是否重复调用和耗尽预算。
- 面试目标：能够回答 `AGENT-LOOP-001`、`AGENT-LOOP-002` 和 `AGENT-LOOP-005`。
- 完成标准：能够逐轮解释 Agent 为什么继续、为什么停止，以及哪一步由确定性代码控制。

### 第 05 课：Planning、Replanning 与确定性控制

- 核心思考：任务越复杂，是否越应该先让模型生成一份完整计划？
- 总纲主归属：Planning(先形成计划)、边执行边规划、Replanning(根据结果重写计划)和确定性代码边界。
- 具体案例：Agent 原计划直接修改配置，但发现当前版本和文档不一致，需要先补充调查。
- ASCII 图主题：Plan-and-Execute(先计划后执行)、ReAct 和混合控制的差异。
- 最小实验：用同一个任务分别实现先计划后执行、边执行边规划和代码固定骨架。
- 失败实验：让第一步得到与计划冲突的新事实，观察计划是否被盲目继续执行。
- 面试目标：能够回答 `AGENT-PLAN-001`、`AGENT-PLAN-002` 和 `AGENT-PLAN-003`。
- 完成标准：能根据任务不确定性、依赖关系和验证成本选择规划方式。

### 第 06 课：验证、终止、预算与失败恢复

- 核心思考：Agent 说“任务完成了”，系统凭什么相信？
- 总纲主归属：Verification Loop(验证不通过就返工)、终止条件、多维预算、重试、降级和 Reward Hacking(钻评测规则漏洞)。
- 具体案例：Agent 修改配置后必须运行测试并回读发布状态，不能只根据工具返回的“success”结束。
- ASCII 图主题：执行、验证、修正、重试、降级和停止状态机。
- 最小实验：为最小 Agent 加入程序断言、最大步数、时间预算和失败分类。
- 失败实验：设计一个只检查输出关键词的错误验证器，让 Agent 找到绕过方式。
- 面试目标：能够回答 `AGENT-LOOP-003`、`AGENT-LOOP-004`、`PROD-DURABLE-003` 和 `PROJECT-DEBUG-002`。
- 完成标准：能区分可重试失败、需要改计划的失败、永久失败和需要人工接管的失败。

## 10. 第三章：信息与状态

### 第 07 课：Context Engineering 不是拼 Prompt

- 核心思考：模型窗口足够大时，把所有资料全部塞进去是否最可靠？
- 总纲主归属：Prompt 与 Context、静态和动态上下文、选择、压缩、隔离、污染和退化。
- 具体案例：Agent 同时拿到项目规则、历史对话、日志、搜索结果和工具说明，需要决定本轮真正加载什么。
- ASCII 图主题：候选信息经过选择、排序、压缩和隔离后进入模型窗口。
- 最小实验：比较全部注入、按需选择和摘要压缩三种上下文策略。
- 失败实验：加入过期规则、无关日志和恶意工具结果，观察决策变化。
- 面试目标：能够回答 `AGENT-CONTEXT-001`、`AGENT-CONTEXT-002` 和 `AGENT-CONTEXT-003`。
- 完成标准：能为任意信息判断是否进入当前 Context，并说明其来源、生命周期和可信度。

### 第 08 课：State、Checkpoint 与 Artifact 如何分工

- 核心思考：消息历史、任务状态、执行检查点和生成文件可以保存到同一个 JSON 里吗？
- 总纲主归属：Working State(当前任务状态)、Session State(会话状态)、持久化状态、Checkpoint(执行检查点)和 Artifact(任务产物文件)。
- 具体案例：Agent 已完成日志分析并生成修复补丁，进程退出后需要从正确位置继续。
- ASCII 图主题：Context、State、Checkpoint、Artifact 和外部业务事实之间的边界。
- 最小实验：持久化一个多步骤任务，重启进程后恢复状态并读取已有 Artifact。
- 失败实验：故意让 Checkpoint 落后于外部写操作，观察恢复后重复执行。
- 面试目标：能够回答 `AGENT-RUNTIME-002`、`PROD-DURABLE-001`、`PROD-DURABLE-002` 和 `PROJECT-ARCH-003`。
- 完成标准：能解释什么需要重建、什么需要持久化、什么必须以外部系统为准。

### 第 09 课：Memory 如何写入、检索、冲突与遗忘

- 核心思考：Agent 每次完成任务后自动总结并写入长期记忆，为什么可能越用越差？
- 总纲主归属：事件经历记忆、事实知识记忆、操作方法记忆、写入、检索、更新、冲突和遗忘。
- 具体案例：Agent 记住某服务只能走旧发布流程，但系统后来完成了迁移。
- ASCII 图主题：任务经验经过筛选、验证、归并和版本化后进入长期记忆。
- 最小实验：分别保存一条事实、一段任务经历和一个操作方法，并在新会话中检索使用。
- 失败实验：写入互相冲突的新旧记忆，验证优先级、版本和撤回。
- 面试目标：能够回答 `AGENT-MEMORY-001`、`AGENT-MEMORY-002` 和 `PROJECT-ARCH-003`。
- 完成标准：能判断一条信息应该进入 Context、State、Memory、Skill 还是 Artifact。

## 11. 第四章：工具与知识

### 第 10 课：Tool Engineering 决定 Agent 能否正确行动

- 核心思考：一个工具功能越多、参数越通用，是否越方便 Agent 使用？
- 总纲主归属：Tool Schema、描述、粒度、返回契约、错误语义、幂等、超时、重试和结果压缩。
- 具体案例：将“查询、修改、发布、回滚”全部放进一个万能工具，与拆成清晰工具集合进行对比。
- ASCII 图主题：模型选择工具、参数校验、权限校验、执行和结果归一化。
- 最小实验：设计两个边界重叠的工具，记录误选，再重构名称、描述和参数。
- 失败实验：制造工具超时、部分成功、重复请求和超大结果。
- 面试目标：能够回答 `AGENT-TOOL-002`、`AGENT-TOOL-003` 和 `AGENT-TOOL-004`。
- 完成标准：能写出模型容易选择、程序容易校验、失败容易诊断的工具契约。

### 第 11 课：Environment、Sandbox、权限与人工审批

- 核心思考：只要 System Prompt 写了“不要执行危险操作”，是否就能安全开放 Shell？
- 总纲主归属：命令、文件、浏览器等执行环境，以及 Sandbox(隔离执行环境)、资源限制、最小权限、人工审批和副作用隔离。
- 具体案例：Agent 可以读取仓库和运行测试，但发布生产配置必须暂停等待审批。

### 第 12 课：MCP、SDK、普通 API 与 A2A 的边界

- 核心思考：接入一个外部能力时，为什么不应该默认先做 MCP Server？

- 具体案例：Agent 需要接入内部发布平台、文档搜索和另一个远程 Agent，分别选择普通 API、MCP 或 A2A。
- ASCII 图主题：应用内 Tool Calling、MCP 能力接入和跨系统 Agent 通信的三层关系。
- 最小实验：实现一个最小 MCP Server，并与直接函数调用对比真实消息和复杂度。

### 第 13 课：RAG 全链路，从切分到引用与评测

- 最小实验：搭建最小知识库，对比关键词、向量和混合检索，并绑定真实出处。

## 12. 第五章：复杂任务运行时

### 第 14 课：如何选择固定链、Router、并行与 Planner-Executor

- 核心思考：只要任务步骤超过三个，是否就应该使用 Graph？
- 总纲主归属：固定串联、条件路由、并行处理、拆分后聚合、规划与执行分离，以及协调者动态分配工作。
- 具体案例：同时处理日志分析、文档检索、代码检查和最终汇总。
- ASCII 图主题：固定串行、条件路由、并行聚合和动态规划的控制权差异。
- 最小实验：用同一任务实现三种编排方式，比较成功率、延迟和调试成本。
- 失败实验：让一个并行子任务超时，观察整体等待、局部降级和结果聚合。

### 第 15 课：Subagent、多 Agent 与 A2A 何时值得

- 核心思考：把任务拆给多个 Agent，为什么经常比单 Agent 更差？

- 具体案例：主 Agent 将日志、文档和代码三个调查任务交给隔离 Subagent，再汇总证据。
- ASCII 图主题：单 Agent、Supervisor-Workers 和跨系统 Agent 协作拓扑。
- 最小实验：比较单 Agent、三个 Subagent 和三个独立 Agent 的成本、成功率与上下文污染。
- 失败实验：让两个 Agent 给出冲突结论，并观察谁负责证据校验和最终决策。
- 面试目标：能够回答 `AGENT-MULTI-001` 和 `AGENT-MULTI-002`。
- 完成标准：能证明增加 Agent 是因为隔离、并行或能力边界，而不是为了架构看起来高级。

### 第 16 课：Graph 如何表达状态、分支与循环

- 核心思考：Graph 是更高级的 Agent Loop，还是另一类工程抽象？
- 总纲主归属：State(运行状态)、Node(处理节点)、Edge(状态转移边)、条件分支、状态合并规则、命令、事件和 Subgraph(子图)。

- ASCII 图主题：Agent 节点与确定性节点混合的状态图。
- 最小实验：将第 04 课的手写 Loop 改造成显式状态图，并输出状态变化事件。
- 失败实验：制造多个节点并发更新同一状态字段，验证 Reducer 和冲突策略。
- 面试目标：能够回答 `AGENT-RUNTIME-001` 和 `PROJECT-ARCH-001`。
- 完成标准：能区分模型决策、代码节点、状态更新和控制流，不把 Graph 当成流程图展示工具。

### 第 17 课：Durable Runtime 与长任务恢复

- 核心思考：保存了 Checkpoint，为什么恢复后仍可能重复发邮件或重复扣款？
- 总纲主归属：执行检查点、持续任务状态线、主动暂停、继续执行、重试、取消、Durable Execution(进程中断后仍可恢复的执行)、幂等、补偿和历史重放。
- 具体案例：Agent 在写入发布平台后进程崩溃，恢复时必须确认外部副作用是否已经发生。
- ASCII 图主题：任务状态、检查点、外部副作用、恢复和补偿之间的时序。
- 最小实验：在不同节点故意杀死进程，再从检查点继续。
- 失败实验：让写操作成功但 Checkpoint 未落盘，验证幂等键和回读机制。
- 面试目标：能够回答 `AGENT-RUNTIME-002`、`AGENT-RUNTIME-003`、`PROD-DURABLE-001` 和 `PROD-DURABLE-003`。
- 完成标准：能设计支持暂停、恢复、审批和不可逆副作用的真实长任务。

## 13. 第六章：Harness

### 第 18 课：Harness 才是现代 Agent 的能力放大器

- 核心思考：为什么同一个模型放进成熟 Agent 产品或简单聊天框后，能力差距会如此巨大？
- 总纲主归属：长期指令、上下文、工具集合、执行环境、权限、结果验证和任务状态。
- 具体案例：比较只有 Shell 的 Agent，与拥有项目规则、测试反馈、任务计划和权限控制的研发 Agent。
- ASCII 图主题：模型和执行循环被上下文、工具、执行环境、权限、反馈与任务状态包围。
- 最小实验：保持模型不变，只调整 Harness 组件并对比任务成功率。
- 失败实验：分别移除项目规则、测试反馈和权限控制，观察能力与风险变化。
- 面试目标：能够回答 `AGENT-HARNESS-001` 和 `PROJECT-ARCH-004`。
- 完成标准：能说明每个 Harness 组件补偿了模型的什么缺口，并能通过消融实验验证价值。

### 第 19 课：Skills 与按需加载

- 核心思考：把所有领域知识和操作步骤写进 System Prompt，为什么不是最稳定的做法？
- 总纲主归属：Skills、领域知识包、Progressive Disclosure(逐步按需披露)、Context Compression 和可替换性。
- 具体案例：研发 Agent 只有在遇到发布、数据库或前端任务时，才加载对应 Skill。
- ASCII 图主题：任务识别、Skill 发现、按需加载、执行和验证。
- 最小实验：比较全量注入、关键词触发和模型选择 Skill 三种策略。
- 失败实验：制造两个功能重叠或内容过期的 Skill，观察检索冲突和错误执行。
- 面试目标：能够回答 `AGENT-HARNESS-002` 和 `AGENT-EVOLVE-002`。
- 完成标准：能解释 Skill、Tool、Prompt、Memory 和 Agent 的边界，并设计 Skill 的测试与版本。

### 第 20 课：Workspace、Hooks 与环境反馈

- 核心思考：Agent 写出了正确代码，为什么整个任务仍然可能失败？
- 总纲主归属：Workspace(任务工作区)、任务产物、Hook(生命周期插入点)、Middleware(调用链中间处理层)、环境反馈和长任务接力。
- 延伸重点：Agent Legibility(让环境对 Agent 可理解)和 Harness Entropy(支撑环境长期堆积造成的混乱)。
- 具体案例：Agent 修改代码后必须自己启动服务、读取日志、运行测试并交付可审计产物。
- ASCII 图主题：Agent 操作 Workspace 后通过编译器、测试、日志和 Hook 获得反馈。
- 最小实验：建立任务 Workspace、测试 Hook 和 Artifact 清单，让 Agent 完成一次可验证修改。
- 失败实验：加入重复、冲突和过期规则，观察 Harness Entropy(支撑环境长期堆积造成的混乱)。
- 面试目标：能够回答 `PROJECT-DEMO-001`、`PROJECT-CODE-001` 和 `PROJECT-REFLECT-001`。
- 完成标准：能让 Agent 自己获得真实环境反馈，并知道何时应该删除而不是继续添加 Harness 组件。

## 14. 第七章：评测与进化

### 第 21 课：Trace 与 Eval 如何证明 Agent 真的变好

- 核心思考：十个演示任务全部成功，为什么仍然不能证明 Agent 可靠？
- 总纲主归属：Trace(完整执行轨迹)、Span(轨迹中的操作片段)、Event(运行事件)、Golden Dataset(有明确验收标准的基准样本集)、离线与在线评测、重复采样和成本预算。
- 具体案例：比较两个研发 Agent 版本，判断提升来自模型、工具、上下文还是偶然性。
- ASCII 图主题：任务样本、多个 Trial、轨迹采集、分层评分和版本对比。
- 最小实验：建立至少十条正常与失败样本，使用程序断言和 LLM Judge 分别评分。
- 失败实验：让评审模型偏爱更长答案，并观察排名是否被错误改变。
- 面试目标：能够回答 `PROD-OBS-001`、`PROD-OBS-002`、`PROJECT-EVAL-001` 和 `PROJECT-EVAL-003`。
- 完成标准：能区分结果、轨迹、检索、环境、安全和效率评测，并说明评分可信度。

### 第 22 课：Loop Engineering 的四层循环

- 核心思考：Agent Loop 已经会反复执行，为什么还需要 Loop Engineering？
- 总纲主归属：Task Loop(完成单次任务的循环)、Verification Loop(验证失败后返工的循环)、Event-driven Loop(事件驱动循环)和 Improvement Loop(系统改进循环)。
- 具体案例：研发 Agent 完成单次任务、验证修复、响应新事件，并根据历史失败改进工具说明。
- ASCII 图主题：四层 Loop 从内到外的包含关系和反馈方向。
- 最小实验：在已有 Agent 外增加验证循环和基于历史 Trace 的离线改进循环。
- 失败实验：让内层任务成功但外层业务指标下降，观察局部优化问题。
- 面试目标：能够回答 `AGENT-LOOPENG-001` 和 `PROD-OBS-004`。
- 完成标准：能说明每层 Loop 的触发条件、状态、反馈和停止机制。

### 第 23 课：受控自进化，不是 Agent 随便改自己

- 核心思考：Agent 自动总结成功经验并修改 Skill，为什么可能快速污染整个系统？
- 总纲主归属：记忆归并、从轨迹中发现可复用 Skill、运行支撑环境适配、保留评测集、非回退门禁、影子运行、灰度和回滚。
- 具体案例：系统从成功 Trace 中生成新版发布 Skill，必须经过独立样本、安全检查和小流量验证。
- ASCII 图主题：Trace、失败归因、候选修改、离线 Eval、审批、发布和回滚。
- 最小实验：生成两个 Skill 或工具描述候选，只允许通过回归门禁的版本进入测试环境。
- 失败实验：将一条偶然成功经验写成通用规则，验证过拟合和错误扩散。
- 面试目标：能够回答 `AGENT-EVOLVE-001` 和 `AGENT-EVOLVE-002`。
- 完成标准：能拆分 Memory、Skill、Harness、代码和模型权重五类演进，并给出各自治理边界。

## 15. 第八章：生产工程

### 第 24 课：Prompt Injection、越权与供应链安全

### 第 25 课：流式、异步、队列、并发与背压

- 完成标准：能解释队列、任务租约、背压、幂等和会话一致性分别解决什么问题。

### 第 26 课：可观测、成本、多租户与故障降级

- 具体案例：某模型供应商延迟升高并间歇失败，系统需要路由、降级且不能串租户数据。
- ASCII 图主题：请求从租户配额、模型路由、Agent Runtime 到监控和降级的生产链路。
- 最小实验：记录任务成功率、工具错误率、Token、延迟和成本，配置一种降级策略。
- 失败实验：模拟模型、向量库和关键工具分别不可用，观察系统是否给出正确降级。
- 面试目标：能够回答 `PROD-OBS-003`、`PROD-COST-001`、`PROD-COST-003`、`PROD-TENANT-001` 和 `PROD-DEGRADE-001`。

## 16. 第九章：贯穿项目

### 第 28 课：故障注入、评测与持续改进实战

### 第 29 课：项目答辩与 Agent 面试总复核

- 总纲主归属：完整体系复核。
- 具体案例：围绕贯穿项目进行架构讲解、代码深挖、线上故障、效果证明和重做取舍。
- ASCII 图主题：一张能够串联 Loop、Graph、Harness、Eval 和生产治理的项目总图。
- 最小实验：进行一次限时项目演示和连续追问模拟，现场打开核心代码与 Trace。
- 失败实验：故意拿掉准备好的标准问法，使用陌生故障和反例追问。
- 面试目标：覆盖[项目追问](../面试题库/05-项目追问.md)，并从其他题库随机抽题进行交叉追问。
- 完成标准：能够先给核心判断，再用图、代码、Trace、指标和失败复盘证明结论。

## 17. 章节验收

每章完成后不立即进入下一章，先做一次综合验收：

1. 不看资料画出本章总图。
2. 随机抽取一条失败 Trace，定位问题层次。
3. 使用本章机制修改一个最小实验。
4. 从[面试题库](../面试题库/README.md)随机抽取三题连续追问。
5. 将有证据的知识点更新为“已理解”或“已实验”。

## 18. 防漂移规则

- 课程顺序只能因认知依赖调整，不能因为某个框架突然流行而整体改道。
- 临时问题先判断属于当前课程、后续课程还是前沿雷达。
- 属于后续课程的问题先给最小定位，不提前展开整章。
- 每节课结束后明确已经覆盖和尚未覆盖的边界。
- 新增课程必须说明原有 30 节为什么无法承载该问题。
- 删除课程必须证明对应知识已经被其他课程完整覆盖。
- 课程中使用的案例、框架和模型可以替换，底层问题与机制保持稳定。

## 19. 上课方式

在当前会话中使用下面的指令即可推进：

```text
开始第 00 课
继续下一节
复习第 04 课
对第 13 课进行面试追问
给我一条第 17 课的故障 Trace
检查我是否通过第 21 课
```

每次开始新课前，我会先说明：

- 当前课程在全局体系中的位置。
- 本节不会展开的相邻知识。
- 本节完成后应该获得的能力。

每次结束时，我会明确：

- 已经掌握的内容。
- 仍然暴露的问题。
- 应沉淀的代码、ASCII 图和面试答案。
- 是否达到进入下一课的条件。
