# Agent 开发课程模板

## 1. 模板定位

每节课都必须遵守这份模板。课程可以因主题调整篇幅，但不能跳过思考、案例、ASCII 图、失败实验、面试攻防和验收。

目标是让一节课同时完成三件事：

```text
建立可迁移心智
  +
形成真实工程证据
  +
产出可直接上场的面试答案
```

课程是学习过程，不是知识的唯一存放位置。开课前读取对应[理解版](../知识模块/理解版模板.md)和[题目版](../知识模块/题目版模板.md)；结课后将稳定机制、失败边界和面试回答回写对应知识模块，课件只保留互动过程、实验记录和本次暴露的问题。

## 2. 一节课的标准结构

### 课程定位

开头先说明：

- 当前课程处在 Agent 系统的哪一层。
- 它依赖哪些已经学过的内容。
- 它为后续哪些课程提供基础。
- 本节明确不展开什么，防止范围漂移。

### 思考题

课程必须从问题开始，优先使用三类问题：

| 类型 | 目的 | 示例 |
|---|---|---|
| 预测题 | 暴露对执行过程的理解 | 工具成功返回后，Agent 下一步一定会结束吗？ |
| 取舍题 | 暴露是否理解适用边界 | 长上下文足够大时还需要 RAG 吗？ |
| 排障题 | 暴露是否能按层定位 | 回答错误应该先改 Prompt、检索还是工具？ |

思考题不追求一次答对。回答后先记录当前判断，再进入机制讲解，最后回看答案发生了什么变化。

### 一句话心智

用一句话回答：

```text
这个机制解决什么问题？
```

一句话中不能出现三个以上未解释术语，也不能使用“提升能力”“形成闭环”代替真实动作。

### ASCII 图

每节课至少画一张 ASCII 图，且一张图只回答一个问题。

可选图型：

```text
调用链：谁调用谁，数据怎样流动
状态图：有哪些状态，何时发生转换
时序图：多个组件按什么顺序交互
分层图：不同机制位于系统哪一层
信任边界图：数据和权限在哪些边界穿越
失败树：一个表象可能由哪些层次导致
```

合格的图必须标明：

- 组件或角色。
- 控制权方向。
- 关键数据或状态。
- 验证点。
- 重要失败路径。

图后只解释关键判断，不逐箭头复述。

### 具体案例

案例必须具备完整输入输出：

```text
用户目标：
已有上下文：
可用工具：
当前状态：
权限边界：
预期输出：
真实副作用：
成功标准：
```

优先使用课程中的企业研发任务 Agent。主题不适合时，可以使用 RAG、客服、Deep Research(深度研究智能体)或 Coding Agent(编码智能体)，但必须说明替换原因。

### 机制推演

按照真实执行顺序展开：

1. 给出关键输入数据。
2. 说明程序和模型分别做什么。
3. 展示状态怎样变化。
4. 标出确定性代码和模型决策的边界。
5. 解释验证和停止发生在哪里。

涉及协议时优先展示真实 JSON、事件或函数签名。涉及代码时先给最小实现，再看框架封装。

### 最小正常实验

实验必须满足：

- 一次只验证一个核心机制。
- 可以重复执行。
- 能观察真实请求、状态、工具结果或 Trace。
- 有程序断言或环境结果作为成功证据。
- 能回答什么时候不需要该机制。

实验完成后记录：

```text
实验假设：
输入：
观察点：
结果：
结论：
```

### 失败实验

每节课至少主动制造一个失败。失败类型从下面选择：

- 模型决策错误。
- 上下文缺失、污染或冲突。
- 工具参数、权限或执行错误。
- 状态丢失、并发冲突或重复副作用。
- 检索、排序或引用错误。
- 验证器误判或评测过拟合。
- 超时、预算耗尽或无法停止。
- 安全注入、越权或数据泄露。

失败实验不能只看报错，需要完成：

```text
表象
  ↓
候选故障层
  ↓
需要检查的证据
  ↓
真实根因
  ↓
最小修复
  ↓
回归验证
```

### 框架映射

完成最小机制后，再选择一到两个代表性框架或系统对照：

- 框架隐藏了哪些状态和协议。
- 它把重试、持久化、审批和 Trace 放在哪里。
- 它新增了什么能力。
- 它带来了什么约束或复杂度。
- 不使用它时如何手写最小版本。

不进行三个以上框架的功能清单竞赛。

## 3. 面试攻防

### 面试题

从[面试题库](../面试题库/README.md)选择一到四道主问题。题库没有对应问题时，先判断是否应该补入题库，不在课件中创造第二套独立编号。

### 30 秒回答

结构固定为：

```text
核心判断
  +
最小机制
  +
一个关键边界
```

目标是先让面试官知道你有完整心智，而不是在背景中绕圈。

### 3 分钟完整回答

结构固定为：

```text
它解决的问题
  ↓
最小机制和 ASCII 图
  ↓
真实案例
  ↓
失败与取舍
  ↓
实验或项目证据
```

### 连续追问

每道题至少准备三层追问：

1. 原理追问：底层协议、状态或算法是什么？
2. 工程追问：失败、并发、权限、成本如何处理？
3. 项目追问：你实际做过什么，结果如何证明？

### 反问前提

高水平回答需要识别问题中的隐藏前提。例如：

```text
“多 Agent 是否更强？”

先确认：
- 任务是否可以并行？
- 是否需要上下文隔离？
- 是否存在独立权限或能力边界？
- 增加 Agent 后由谁验证冲突结果？
```

反问不是回避问题，而是明确方案成立的约束。

## 4. 课程验收

一节课通过需要同时满足：

| 验收项 | 通过标准 |
|---|---|
| 心智 | 不看资料说清它解决的问题和系统位置 |
| ASCII 图 | 能独立画出调用链、状态或边界 |
| 实验 | 完成正常和失败实验，并保留证据 |
| 排障 | 能根据 Trace 判断错误层次 |
| 边界 | 能说明什么时候不应该使用该机制 |
| 面试 | 能完成 30 秒回答和连续追问 |
| 迁移 | 更换框架后仍能识别同一底层机制 |

不满足其中任一项时，不把对应知识标记为“已实验”。

## 5. 课程产物

每节课完成后应形成：

```text
课程笔记
ASCII 图
最小实验代码
失败 Case 与 Trace
面试 30 秒答案
面试 3 分钟答案
连续追问记录
仍未解决的问题
对应理解版的修订
对应题目版的修订
```

后续正式课件建议放在：

```text
docs/课程/课件/第00课-标题.md
docs/课程/课件/第01课-标题.md
```

不提前创建空课件。开始一节课时创建对应文件，完成验收后再视为正式课件。

## 7. 授课表达规则

- 先给框架，再展开案例，最后用一句话收束。
- 抽象概念先给最简心智和图，再给代码。
- 较难英文第一次出现时使用`英文(精简通俗注释)`。
- 不使用字母等级或课程模块缩写代替自然语言。
- 不连续堆框架名称证明内容前沿。
- 不把用户暂时答错当成失败，重点追踪心智如何改变。
- 被指出表达不清时，先换组织方式，再补充更多内容。
- 每节课结束必须明确是否通过验收，不能用“应该差不多懂了”收尾。
