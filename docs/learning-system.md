# 学习机制

## 1. 核心判断

单独使用任何一种学习方式都会失衡：

| 方式 | 优点 | 单独使用的风险 |
|---|---|---|
| 系统课程 | 覆盖完整、概念连续 | 容易被课程体量拖慢，理解停留在输入 |
| 项目驱动 | 反馈真实、容易形成产出 | 项目没遇到的内容会被遗漏 |
| 零散实验 | 能快速验证单个机制 | 知识之间缺少连接 |
| 面试题驱动 | 容易暴露术语盲区 | 容易背结论，缺少真实能力 |

本仓库采用三条主线和一条保障线：

```text
系统知识线：保证完整覆盖
机制实验线：保证真正理解
贯穿项目线：保证知识串联
覆盖与评测线：保证没有自我感觉良好
```

## 2. 系统知识线

系统知识线以 [知识地图](knowledge-map.md) 为边界，不以某个课程目录或某个项目为边界。

每个知识点使用统一的知识卡片结构：

```text
名称：
它解决的问题：
位于 Agent 系统的哪一层：
最小工作机制：
关键输入与输出：
适用场景：
不适用场景：
常见失败：
与相邻概念的区别：
最小实验：
框架如何封装：
掌握证据：
```

知识卡片的目标是建立可迁移理解，避免只记住某个框架类名。

## 3. 机制实验线

每个主干知识点都应该有最小实验，但不要求每个实验都进入贯穿项目。

一个合格的机制实验需要满足：

1. 只验证一个核心机制。
2. 输入、输出和失败条件明确。
3. 能观察模型请求、工具结果、状态变化或执行轨迹。
4. 至少包含一个正常 Case 和一个失败 Case。
5. 不依赖大量框架魔法。
6. 可以通过测试或断言重复验证。

示例：

| 知识点 | 最小实验 |
|---|---|
| Tool Calling | 手写一次模型选工具、参数校验、执行和结果回填 |
| Context Compression | 对超长消息做窗口裁剪与摘要，对比信息损失 |
| Memory | 保存任务状态，启动新会话后恢复并继续 |
| Router | 对固定样本路由，统计错误路由及原因 |
| Graph Interrupt | 在高风险节点暂停，审批后从检查点恢复 |
| RAG | 分别制造召回失败和生成失败并定位原因 |
| Prompt Injection | 在工具结果中注入恶意指令，验证隔离策略 |
| Eval | 对同一组样本比较两个 Prompt 或两个模型版本 |

## 4. 贯穿项目线

贯穿项目承担四个职责：

- 把不同模块连接成完整系统。
- 暴露模块之间的真实边界。
- 提供可重复的成功和失败样本。
- 沉淀架构、代码、Trace、评测和复盘证据。

贯穿项目不承担两个职责：

- 不负责决定哪些知识需要学习。
- 不要求所有知识都强行塞入同一个项目。

当某个知识点不适合进入贯穿项目时，用独立机制实验完成掌握证明。

## 5. 覆盖与评测线

[覆盖台账](coverage-ledger.md) 是防遗漏机制。

每个知识点使用以下状态：

| 状态 | 含义 |
|---|---|
| 未开始 | 尚未形成稳定认识 |
| 已理解 | 能解释机制、边界和失败模式 |
| 已实验 | 完成最小实现和失败 Case |
| 已整合 | 已接入贯穿项目或综合实验 |
| 已复核 | 间隔一段时间后仍能解释、实现或排障 |

状态升级必须有证据，证据可以是：

- 知识卡片。
- 可运行代码。
- 测试结果。
- Trace 或执行日志。
- 失败分析。
- 对比实验。
- 架构图。
- 复盘记录。

“看完课程”本身不作为掌握证据。

## 6. 单模块学习闭环

每个模块采用同一套闭环：

```text
建立全局问题
    ↓
学习核心概念
    ↓
完成最小机制实验
    ↓
制造并分析失败
    ↓
查看框架如何封装
    ↓
接入贯穿项目或综合实验
    ↓
更新覆盖台账
    ↓
间隔复核
```

学习顺序不是“先把全部理论看完，再统一实践”，也不是“项目遇到什么才查什么”。每个模块内部完成一次小闭环，然后继续扩展全局地图。

## 7. 框架学习原则

- 第一遍先理解协议、状态和控制流，再看框架抽象。
- 主框架用于提高实现效率，对照框架用于验证认知可迁移。
- 同一机制不同时并行学习三个以上框架。
- 框架 API 变化时，知识卡片中的机制和边界应该仍然成立。
- 框架对比只比较真实问题，例如持久化、审批、流式事件和恢复，不做功能清单竞赛。

## 8. 原课程材料的使用方式

| 材料 | 使用方式 |
|---|---|
| JavaAI、PythonAI 脑图 | 用作知识索引和遗漏检查 |
| RAG、客服、办公 Agent 架构图 | 用作系统设计检查表 |
| 面试题库 | 用作认知盲区扫描和阶段复核题库 |
| 机器学习、NLP、微调内容 | 按知识地图中的支线深度学习 |
| 框架专项内容 | 在完成机制实验后选择性阅读 |

材料中的顺序、课时和框架划分不直接继承到本仓库。

## 9. 后续需要共同决定

首版暂时不确定以下内容：

1. 各模块的具体资料来源。
2. 第一轮的时间预算和模块粒度。
3. 每个模块需要多少个机制实验。
4. 主实验语言和主框架。
5. 贯穿项目选题。
6. 阶段验收和复习频率。
7. 是否为每个模块维护单独目录。

这些决策应该在知识地图稳定后逐项讨论，而不是一次性全部预设。
