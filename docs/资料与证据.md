# Agent 开发资料与证据

## 1. 文档定位

这份文档管理学习资料、证据等级和知识更新规则。

它不定义学习顺序。学习范围和章节关系以[学习总纲](学习总纲.md)为准，尚未稳定的新方向进入[前沿雷达](前沿雷达.md)。

最后核对日期：`2026-07-30`。

## 2. 为什么需要证据分层

Agent 领域变化快，同一个词可能同时出现在论文、框架宣传、课程和社交媒体中，但它们能证明的事情不同。

如果不区分证据强度，学习路径很容易从“过拟合一套课程”变成“过拟合一个开源项目或一轮热点”。

## 3. 证据等级

| 证据等级 | 资料类型 | 可以证明什么 | 使用限制 |
|---|---|---|---|
| 一级 | 官方协议、正式规范、官方 API 文档、正式论文 | 真实协议、数据结构、研究方法和原始结论 | 仍需核对版本和实验边界 |
| 二级 | 官方源码、RFC(设计提案)、架构文档、维护者技术文章 | 实际实现、工程取舍和演进方向 | 单个项目的设计不能自动推广到所有系统 |
| 三级 | 独立复现、Benchmark(基准评测)、高质量工程复盘 | 方法在不同环境中的效果和失败条件 | 需要检查样本、指标和复现完整性 |
| 四级 | 系统课程、专业书籍、教程和技术博客 | 建立连续知识、获得直觉和查漏补缺 | 不能单独定义前沿主干 |
| 五级 | 推特、播客、演讲、社区讨论和二手总结 | 发现新术语、新项目和争议 | 只作为线索，不直接写成事实 |
| 禁用 | 来源不明的泄漏代码、无法确认版本的反编译材料 | 最多提出待验证假设 | 不作为主参考、实现依赖或正式证据 |

## 4. 知识进入主干的最低门槛

一个新概念进入`学习总纲.md`，至少满足下面两类证据：

1. 有一级或二级来源说明它真实存在，并能确认机制。
2. 有源码、最小实验、独立复现或评测说明它解决了真实问题。

同时必须回答：

- 它解决的是新问题，还是已有概念的新名字？
- 它应该成为独立章节，还是归入现有章节？
- 它是否跨模型、跨框架成立？
- 不使用它会出现什么可观察失败？
- 它带来的复杂度是否超过收益？

## 5. 核心原理资料

### Agent 设计与编排

| 资料 | 主要用途 | 阅读重点 |
|---|---|---|
| [Anthropic：Building Effective Agents](https://www.anthropic.com/engineering/building-effective-agents) | 建立 Workflow(固定工作流)与 Agent 的边界 | Prompt Chaining、Router、Parallelization、Orchestrator-Workers、Evaluator-Optimizer |
| [OpenAI Agents SDK](https://openai.github.io/openai-agents-python/) | 对照 Agent、Handoff、Guardrail、Session 和 Trace 的工程实现 | 原始协议与 SDK 封装边界 |
| [Google Agent Development Kit](https://google.github.io/adk-docs/) | 对照 Agent、Workflow、Session、Memory、Eval 和部署 | Runtime(运行时)与应用代码的责任边界 |

### Context 与 Harness

| 资料 | 主要用途 | 阅读重点 |
|---|---|---|
| [Anthropic：Effective Context Engineering for AI Agents](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) | 建立上下文选择、压缩、记忆和 Subagent 隔离心智 | Context 不是简单拼接 Prompt |
| [OpenAI：Harness Engineering](https://openai.com/index/harness-engineering/) | 理解环境、反馈、可读性和持续清理如何影响 Agent 能力 | Agent Legibility(让环境对 Agent 可理解)、Harness Entropy(支撑环境长期堆积造成的混乱) |
| [Claude Code：Context Window](https://code.claude.com/docs/en/context-window) | 观察真实 Coding Agent(编程智能体)的上下文组成 | 自动加载内容、Compaction 和 Token 成本 |
| [Claude Code：Memory](https://code.claude.com/docs/en/memory) | 对照项目指令、记忆和上下文加载 | 指令文件不是强制配置，而是模型上下文 |

### Loop Engineering 与持续改进

| 资料 | 主要用途 | 阅读重点 |
|---|---|---|
| [LangChain：The Art of Loop Engineering](https://www.langchain.com/blog/the-art-of-loop-engineering) | 区分任务、验证、事件和系统改进循环 | 多层 Loop 如何叠加，而不是把 Loop 当成单一 while 循环 |
| [Darwin Gödel Machine](https://arxiv.org/abs/2505.22954) | 研究 Agent 修改自身代码并用基准验证的开放式探索 | 代码自修改、候选归档、经验验证和安全边界 |
| [SkillWeaver](https://arxiv.org/abs/2504.07079) | 研究 Web Agent 如何探索并形成可复用 Skill | Skill 的发现、练习、抽象和迁移 |
| [MUSE-Autoskill](https://arxiv.org/abs/2605.27366) | 研究 Skill 创建、记忆、管理、评测和迭代生命周期 | Skill 不能只生成，还要测试、版本和维护 |

这些论文用于建立问题分类和实验假设，不表示其方法已经达到通用生产标准。

## 6. Runtime 与协议资料

### Graph 与可恢复执行

| 资料 | 主要用途 | 阅读重点 |
|---|---|---|
| [LangGraph Overview](https://docs.langchain.com/oss/python/langgraph/overview) | 学习 State、Node、Edge、Graph 和 Runtime | Agent Loop 与 Graph Runtime 的包含关系 |
| [LangGraph Durable Execution](https://docs.langchain.com/oss/python/langgraph/durable-execution) | 学习持久化、重放、幂等和恢复 | Checkpoint 不等于外部副作用安全 |
| [LangGraph Interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts) | 学习暂停、人工审批和继续执行 | Interrupt 与异常失败的区别 |

### 工具与 Agent 协议

| 资料 | 主要用途 | 阅读重点 |
|---|---|---|
| [Model Context Protocol](https://modelcontextprotocol.io/specification/latest) | 学习 MCP 的正式架构和消息协议 | Host、Client、Server、Transport、Capability 与安全边界 |
| [Agent2Agent Protocol](https://a2a-protocol.org/latest/specification/) | 学习独立 Agent 系统之间的发现、通信和任务协作 | A2A 与 MCP、普通 REST API、框架内 Handoff 的区别 |

协议学习优先读取正式规范，再阅读 SDK 示例。不要从某个框架的辅助类反推协议本身。

## 7. 代表性开源系统

开源系统用于研究“机制如何组合”，不直接作为学习目录。

### DeerFlow

官方入口：[ByteDance DeerFlow](https://github.com/bytedance/deer-flow)

适合研究：

- 长任务规划与执行。
- Subagent 的任务隔离和并行。
- Sandbox 与执行环境。
- Context、Memory、Skills 和工具如何组合。
- Agent Harness 的系统边界。

需要验证：

- README 描述与实际代码路径是否一致。
- Skill Self-Evolution(技能自演进)是正式能力、实验功能还是设计提案。
- 每次版本升级后的 Runtime、状态和配置变化。

### Hermes Agent

官方入口：

- [NousResearch Hermes Agent](https://github.com/NousResearch/hermes-agent)
- [Hermes Agent Documentation](https://hermes-agent.nousresearch.com/docs/)

适合研究：

- 后台执行和持续任务。
- Memory 与 Skill 的沉淀。
- 从执行经验中更新知识。
- Skill 的审批、归档、整理和回滚。
- 自我改进与知识库治理的边界。

需要验证：

- 自动生成或修改的 Skill 是否经过独立任务评测。
- 错误经验如何撤回。
- 长期积累后 Skill 检索冲突和上下文成本。

### Claude Code

官方入口：

- [Claude Code Documentation](https://code.claude.com/docs/en/overview)
- [Claude Code Subagents](https://code.claude.com/docs/en/sub-agents)
- [Claude Code Hooks](https://code.claude.com/docs/en/hooks)
- [Claude Code Skills](https://code.claude.com/docs/en/skills)

适合研究：

- 项目指令和上下文加载。
- Tool、Skill、Hook、Subagent 和插件边界。
- Coding Agent 的 Compaction、权限和长任务机制。
- 用户可观察到的 Harness 行为。

不采用所谓“泄漏的 Claude Code 源码”作为主资料。原因不是其中一定没有信息，而是来源、版本、完整性和合法性无法稳定确认。正确使用方式是从官方文档和可观察行为提出假设，再通过黑盒实验或官方 SDK 验证。

## 9. 社交媒体使用规则

推特、播客和演讲主要用于建立前沿雷达：

```text
发现观点
   ↓
找到作者原文、代码、RFC 或论文
   ↓
核对版本和上下文
   ↓
完成最小实验
   ↓
进入前沿雷达或知识主干
```

如果找不到原始来源，只记录为“未验证线索”，不写入知识卡片的事实部分。

## 11. 更新机制

### 每月快速扫描

- 模型 API、MCP 和 A2A 规范变化。
- 主 Runtime 的状态、持久化、审批和 Eval 变化。
- DeerFlow、Hermes、Claude Code 等样本系统的关键发布。
- 前沿雷达中是否出现多个独立来源支持同一新机制。

### 每季度主干复核

- 是否出现新的稳定问题分类。
- 是否有旧章节已经被更高层抽象替代。
- 是否有热点概念应降级或归档。
- 现有最小实验是否仍能验证真实机制。
- 资料链接、版本和结论是否仍一致。

### 进入主干前

任何新增内容先更新证据卡片和前沿雷达，再决定是否修改学习总纲。
