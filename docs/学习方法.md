# Agent 开发学习方法

## 1. 文档定位

这份文档只定义每个知识点如何学习，不定义学习范围。

学习范围、章节顺序和掌握要求统一以[学习总纲](学习总纲.md)为准，学习状态统一记录在[学习进度](学习进度.md)。

## 2. 核心方法

单独使用任何一种学习方式都会失衡：

| 学习方式 | 优点 | 单独使用的风险 |
|---|---|---|
| 系统课程 | 概念连续、覆盖较广 | 容易被体量拖慢，理解停留在输入 |
| 项目驱动 | 反馈真实、容易形成产出 | 项目没遇到的内容容易遗漏 |
| 零散实验 | 能快速看清单个机制 | 知识之间缺少连接 |
| 框架教程 | 上手速度快 | 容易把框架 API 误认为底层原理 |
| 面试题 | 容易暴露术语盲区 | 容易背结论，缺少真实排障能力 |
| 论文追踪 | 能接触前沿方法 | 容易投入过深且缺少工程闭环 |

本仓库采用四条学习线：

```text
知识总纲线：保证完整覆盖
机制实验线：保证真正理解
贯穿项目线：保证知识连接
评测复核线：保证结论可验证
```

知识内容本身采用两种互相校验的版本：

```text
理解版：把概念推导成可迁移心智
题目版：把心智压缩成可上场答案
```

两种版本的结构见[知识模块](知识模块/README.md)。理解版不是长篇百科，题目版也不是孤立背诵材料。

## 3. 单个知识点的学习闭环

每个主干知识点按同一套流程学习：

```text
明确它解决什么问题
        ↓
在理解版中推导最小工作机制
        ↓
完成一个最小正常实验
        ↓
主动制造一个失败场景
        ↓
查看框架如何封装
        ↓
在题目版中形成面试回答和追问链
        ↓
接入综合实验或贯穿项目
        ↓
记录掌握证据
        ↓
间隔一段时间后复核
```

任何一步都不能由“看完文章”代替。

## 4. 知识卡片

知识卡片是理解版中的最小索引，不再作为独立的第三套正文。每个知识点使用统一结构沉淀：

```text
名称：
它解决的问题：
位于 Agent 系统的哪一层：
最小工作机制：
关键输入和输出：
适用场景：
不适用场景：
常见失败：
与相邻概念的区别：
最小实验：
框架如何封装：
掌握证据：
仍未解决的问题：
```

知识卡片的目标是形成可迁移理解。框架 API 变化后，卡片中的问题、机制、边界和失败模式仍然应该成立。

当一个知识点可以独立形成完整工程问题时，将它提升为知识模块，使用[理解版模板](知识模块/理解版模板.md)和[题目版模板](知识模块/题目版模板.md)沉淀。

## 5. 最小机制实验

### 5.1 合格标准

一个合格的机制实验需要满足：

1. 一次只验证一个核心机制。
2. 输入、输出和成功条件明确。
3. 能看到真实模型请求、工具结果、状态变化或 Trace(完整执行轨迹)。
4. 至少包含一个正常 Case(用例)和一个失败 Case。
5. 不依赖大量框架魔法。
6. 可以通过测试、断言或环境结果重复验证。
7. 实验结论能回答“什么时候不用它”。

### 5.2 典型实验

| 知识点 | 最小实验 |
|---|---|
| Tool Calling | 手写模型选工具、参数校验、执行和结果回填 |
| Context Compression | 裁剪并摘要超长消息，对比关键事实损失 |
| Memory | 保存任务状态，启动新会话后恢复并继续 |
| Router | 对固定样本路由，统计错误路由和原因 |
| Graph Interrupt | 在高风险节点暂停，审批后从检查点恢复 |
| RAG | 分别制造召回失败和生成失败并定位原因 |
| Prompt Injection | 在用户输入和工具结果中注入恶意指令 |
| Eval | 对同一组样本比较两个 Prompt 或 Harness 版本 |
| Skill Evolution | 从成功轨迹生成 Skill，用独立样本验证并尝试回滚 |

### 5.3 失败优先

只跑通正常流程无法证明理解。每个实验至少主动制造一种失败：

- 输入不完整或存在冲突。
- 模型选择错误工具。
- 工具参数不合法。
- 工具超时或返回恶意内容。
- 状态丢失或重复执行。
- 检索没有召回关键证据。
- 验证器误判。
- 预算耗尽或循环无法停止。
- 新版本提升当前样本但破坏历史能力。

## 6. 掌握状态

不使用抽象等级编码，直接记录学习证据：

| 状态 | 含义 | 最低证据 |
|---|---|---|
| 未开始 | 尚未形成稳定认识 | 无 |
| 已理解 | 能解释问题、机制、边界和常见失败 | 知识卡片或口头复述记录 |
| 已实验 | 能独立完成最小实现和失败实验 | 代码、测试、Trace 或实验报告 |
| 已整合 | 已接入贯穿项目或综合实验 | 项目提交、架构图和端到端验证 |
| 已复核 | 间隔一段时间后仍能解释、实现或排障 | 复测、重做或故障分析 |

“看过课程”“收藏文章”“运行官方 Demo”本身都不能升级状态。

## 7. 贯穿项目

贯穿项目承担四个职责：

- 连接不同章节。
- 暴露模块之间的真实边界。
- 提供可重复的正常和失败样本。
- 沉淀架构、代码、Trace、Eval 和复盘证据。

贯穿项目不承担两个职责：

- 不负责决定哪些知识必须学习。
- 不要求所有知识都强行塞入同一个项目。

不适合进入贯穿项目的知识点，用独立机制实验完成掌握证明。

## 8. 框架学习策略

### 8.1 学习顺序

```text
真实协议和数据结构
        ↓
手写最小机制
        ↓
主框架实现
        ↓
对照框架验证迁移性
```

### 8.2 主框架与对照框架

- 主框架用于提高实验和项目效率。
- 对照框架用于验证心智是否依赖某个 API。
- 同一机制不同时学习三个以上框架。
- 只比较真实问题，不做功能清单竞赛。

适合比较的问题包括：

- 状态如何保存。
- 中断后如何恢复。
- 人工审批如何表达。
- 流式事件如何输出。
- 工具错误如何传递。
- Subagent 上下文如何隔离。
- Trace 和 Eval 如何接入。

### 8.3 框架降级原则

当一个框架示例无法显示真实请求、状态或执行轨迹时，先退回原生 API 或手写实现，不继续在封装层猜测。

## 9. 资料学习策略

资料按证据强度使用：

```text
官方协议、官方文档、正式论文
        ↓
官方源码、RFC、架构文档
        ↓
高质量复现、Benchmark、工程复盘
        ↓
课程、博客、视频
        ↓
推特、播客和二手总结
```

低层资料适合发现问题和获得直觉，高层资料负责确认真实机制。

一个热点观点进入知识卡片前，至少完成：

```text
发现线索
   ↓
找到原始来源
   ↓
核对代码或协议
   ↓
完成最小复现
   ↓
判断是否进入主干
```

具体资料见[资料与证据](资料与证据.md)，尚未稳定的新概念见[前沿雷达](前沿雷达.md)。

## 10. 高 ROI 投入规则

### 10.1 优先投入

- 能跨模型、跨语言、跨框架复用的机制。
- Agent 真实请求、状态和工具契约。
- 高频失败边界和可恢复性。
- Context、Tool、Harness 和 Eval 等直接决定系统能力的部分。
- 可以通过最小实验快速证伪的内容。

### 10.2 延后投入

- 只为记忆框架类名和配置项服务的内容。
- 尚无项目需求的模型训练细节。
- 只有宣传描述、没有代码或实验的热点概念。
- 多个功能高度相似的框架横向测评。
- 无法形成可重复证据的 Demo。

### 10.3 停止条件

一个知识点达到本轮要求后立即停止扩张：

- 已能解释机制和边界。
- 已完成正常与失败实验。
- 已能定位到系统中的位置。
- 已知道何时不用它。

除非贯穿项目暴露新问题，否则不继续无边界收集资料。

## 11. 每章学习节奏

每章采用三阶段：

### 建立地图

- 阅读总纲中的章节目标和完整知识点。
- 用自己的话画出最小机制图。
- 标记不理解和容易混淆的概念。

### 完成实验

- 先做原生或手写实验。
- 查看真实请求、状态和 Trace。
- 制造失败并定位。
- 再阅读框架实现。

### 形成证据

- 完成或修订对应理解版。
- 完成对应题目版的 30 秒、3 分钟和连续追问。
- 保存代码、测试、Trace 和失败分析。
- 更新学习进度。
- 记录仍未解决的问题，不强行给出结论。

## 12. 阶段复核

每完成一个大部分，至少做一次复核：

1. 不看资料重画该部分心智图。
2. 随机抽取一个知识点重新实现最小机制。
3. 给出一个失败 Trace，判断问题属于模型、上下文、工具、状态、编排、Harness 还是评测。
4. 使用另一种框架或原生 API 重做一个核心实验。
5. 检查是否出现“术语知道但不会验证”的条目。

间隔复核的结果更新到[学习进度](学习进度.md)，而不是重新复制一份总结目录。

## 13. 原始课程材料的使用方式

| 材料 | 使用方式 |
|---|---|
| JavaAI、PythonAI 脑图 | 知识索引和遗漏检查 |
| RAG、客服、办公 Agent 架构图 | 系统设计检查表 |
| 面试题库 | 认知盲区扫描和阶段复核 |
| 机器学习、NLP、微调内容 | 按总纲中的支线要求学习 |
| 框架专项内容 | 完成机制实验后选择性阅读 |

课程中的顺序、课时和框架划分不直接继承到本仓库。

## 14. 后续需要共同决定

- 第一轮时间预算和每章时间上限。
- 主实验语言。
- 主框架和对照框架。
- 贯穿项目选题。
- 阶段评测集和复习频率。
- 知识卡片、实验和 Trace 的目录结构。
- 第一批理解版和题目版的模块边界。
