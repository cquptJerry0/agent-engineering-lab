# ADR-0001：采用四线并行的 Agent 学习架构

- 状态：已接受
- 日期：2026-07-30

## 背景

现有课程材料覆盖 JavaAI、PythonAI、RAG、Agent、MCP、微调、多模态、企业项目和面试题，范围足够广，但存在三个问题：

1. 线性学习体量过大，主干和支线投入接近。
2. 课程以语言和框架划分，难以形成跨框架的统一 Agent 心智。
3. 如果完全改成项目驱动，项目没有遇到的机制会被遗漏。

目标是快速掌握核心原理，同时建立完整、可迁移、能串联主流 Agent 体系的知识结构。

## 决策

采用以下四条并行学习线：

```text
系统知识线：由知识地图保证完整覆盖
机制实验线：用最小实现和失败 Case 保证理解
贯穿项目线：连接不同模块并验证综合能力
覆盖与评测线：记录证据、发现遗漏并做间隔复核
```

知识地图不按框架划分，而按模型原语、Loop、Context、Tools、Retrieval、Orchestration、Graph、Harness、Evaluation 和系统工程划分。

每个知识点定义目标掌握等级。主干原则上达到 L3，支线第一轮达到 L1 或 L2。

## 原因

这套结构同时满足四个约束：

- 系统知识线避免项目偶然性造成遗漏。
- 机制实验避免只会使用框架。
- 贯穿项目避免知识点彼此割裂。
- 覆盖台账避免把“看过”误判为“掌握”。

## 未选择的方案

### 方案一：完全按照原课程线性学习

没有采用。课程覆盖完整，但主线过长，框架和语言重复较多，难以快速形成 Agent 核心心智。

### 方案二：完全项目驱动

没有采用。项目反馈真实，但学习范围会受到项目场景限制，容易遗漏未触发的核心机制。

### 方案三：只学习最新框架

没有采用。框架能提高短期实现速度，但 API 和抽象会持续变化，无法替代协议、状态、控制流和失败边界。

### 方案四：以面试题为目录

没有采用。题库适合查漏补缺，不适合承担知识组织和能力验证。

## 影响

正向影响：

- 可以完整覆盖 Agent 核心知识，同时控制不同模块的投入深度。
- 学习结果会沉淀为知识卡片、实验、测试、Trace 和项目证据。
- 后续更换模型、语言或框架时，已有心智仍然可以复用。

成本：

- 需要持续维护知识地图和覆盖台账。
- 需要为关键机制设计独立实验，短期产出速度可能低于直接套框架。
- 需要明确阶段验收，否则四条学习线可能同时扩张。

## 暂不决定

- 具体学习排期。
- 主实验语言。
- 主框架。
- 贯穿项目选题。
- 每个模块的资料清单。
- 阶段评测方式。

这些内容将在后续讨论中分别形成新的 ADR 或学习计划。
