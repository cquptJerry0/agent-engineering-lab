# ADR-0001：采用稳定知识图、动态课程与双轨产物

- 状态：已接受
- 日期：2026-08-10

## 背景

早期结构同时维护学习总纲、知识模块、固定 30 课、课程模板、学习方法和进度。虽然知识覆盖完整，但同一职责被多份文档重复表达：

- 学习总纲、知识模块和课程都在组织知识。
- 学习方法、课程模板和 Skill 都在定义授课行为。
- 题目版、课程面试答案和面试题库都在承载面试内容。

固定课表还会把某一时刻的知识分组和学习顺序变成长期约束，使 Agent 更关注完成课号，而不是根据真实掌握状态选择下一步。

## 决策

采用三层运行模型：

```text
稳定结构
  学习总纲、面试题库、资料索引

动态状态
  学习进度、薄弱点、项目与面试目标

生成视图
  当前课程单元
```

不再维护固定完整课表。每次学习前从总纲和进度中动态选择一组存在因果关系的知识点，编译成一个 CU。

每个 CU 使用双轨产物：

```text
推导式理解
  → 使用贯穿案例建立机制心智

面试训练
  → 将稳定心智压缩成可上场答案
```

## 文档职责

| 文档 | 唯一职责 |
|---|---|
| 学习总纲 | 唯一知识边界和依赖关系 |
| 学习进度 | 状态、薄弱点和证据 |
| 动态课程 | 实际生成并学习过的 CU |
| 面试题库 | 真实题目和来源 |
| 资料索引 | 稳定证据和待验证方向 |

授课方法和产物合同只保存在 Skill 中，不再建立独立学习方法和课程模板文档。

Skill 只保留两层职责：

```text
architecture-research
  → 研究来源、归一概念、建立唯一知识总纲

course-delivery-orchestrator
  → 根据总纲、进度和目标动态设计并交付双轨 CU
```

不再单独维护“课程设计”与“课程交付”两个 Skill，因为它们共享动态选课、知识聚合、双轨产物和状态写回的同一控制权。

## 动态选课原则

一个 CU 的知识点必须：

1. 共同回答一个完整问题。
2. 能在同一案例中保持目标、输入和状态连续。
3. 前一机制留下的问题会自然引出下一机制。
4. 能形成端到端 Trace、实验或复述证据。

课程编号只表示生成顺序，不代表长期固定的知识顺序。

## 影响

正向影响：

- 消除知识模块和课程正文的重复。
- 课程能响应学习状态、项目需求和遗忘情况。
- 推导式理解更容易形成连续因果链。
- 面试训练拥有明确且唯一的知识来源。

成本：

- 每次开课前都需要读取总纲和进度。
- 动态分组需要语义判断，不能只依赖固定脚本。
- 课程数量无法提前承诺。
- 需要通过实际 CU 持续校正 Skill。

## 未选择的方案

### 固定完整课表

没有采用。固定课表适合公开班级排期，不适合根据个人掌握状态持续调整的学习系统。

### 独立知识模块目录

没有采用。实际 CU 已经包含推导式理解和面试训练，再增加知识模块会产生第三层正文。

### 只使用项目驱动

没有采用。项目负责串联知识，但学习总纲仍负责防止项目未触发的核心机制被遗漏。
