# ADR-0001：采用四线学习与双轨内容架构

- 状态：已接受
- 日期：2026-07-30

## 背景

现有课程材料覆盖 JavaAI、PythonAI、RAG、Agent、MCP、微调、多模态、企业项目和面试题，范围足够广，但存在三个问题：

1. 线性学习体量过大，主干和支线投入接近。
2. 课程以语言和框架划分，难以形成跨框架的统一 Agent 心智。
3. 如果完全改成项目驱动，项目没有遇到的机制会被遗漏。

目标是快速掌握核心原理，同时建立完整、可迁移、能串联主流 Agent 体系的知识结构。

## 决策

采用以下四条并行学习线：

```text
系统知识线：由学习总纲保证完整覆盖
机制实验线：用最小实现和失败 Case 保证理解
贯穿项目线：连接不同模块并验证综合能力
覆盖与评测线：记录证据、发现遗漏并做间隔复核
```

学习总纲不按框架划分，而按真实问题和稳定机制划分：

- 模型原语与模型交互。
- Agent Loop(智能体执行循环)。
- Context(模型本轮可见信息)、工具、检索和知识。
- Orchestration(任务编排)与 Graph(状态图运行时)。
- Harness(智能体运行支撑环境)。
- Evaluation(系统化评测)、持续改进和生产系统工程。

每个知识点直接写明第一轮掌握要求，不使用字母等级编码。主干原则上需要能解释机制、完成最小实验并分析失败边界；支线第一轮只建立定位，达到触发条件后再深入。

在四条学习线之上，增加“理解版 + 题目版”双轨内容架构：

```text
学习总纲
  ↓
理解版：问题、推导、机制、案例、失败、实验、边界
  ↓
题目版：核心判断、面试回答、连续追问、真实证据
  ↓
课程互动与实验
  ↓
学习进度与间隔复核
```

双轨结构复用旧学习仓库中“推导式理解、思维导图、分类满分答案和面试输出手册”的成熟方法，但压缩了重复产物：全局脑图由学习总纲承担，模块脑图放在理解版末尾，满分答案和输出手册统一由题目版承担。

## 原因

这套结构同时满足四个约束：

- 系统知识线避免项目偶然性造成遗漏。
- 机制实验避免只会使用框架。
- 贯穿项目避免知识点彼此割裂。
- 学习进度和评测证据避免把“看过”误判为“掌握”。
- 理解版避免只背答案，题目版避免看懂后无法形成面试输出。

## 未选择的方案

### 方案一：完全按照原课程线性学习

没有采用。课程覆盖完整，但主线过长，框架和语言重复较多，难以快速形成 Agent 核心心智。

### 方案二：完全项目驱动

没有采用。项目反馈真实，但学习范围会受到项目场景限制，容易遗漏未触发的核心机制。

### 方案三：只学习最新框架

没有采用。框架能提高短期实现速度，但 API 和抽象会持续变化，无法替代协议、状态、控制流和失败边界。

### 方案四：以面试题为目录

没有采用。题库适合查漏补缺，不适合承担知识组织和能力验证。

### 方案五：为每个模块复制四套完整正文

没有采用。旧仓库的四层结构有效，但如果机械复制到 Agent 体系，会重新造成文档职责重叠。当前使用总纲、理解版和题目版承接四种能力，课程与题库只引用它们。

## 影响

正向影响：

- 可以完整覆盖 Agent 核心知识，同时控制不同模块的投入深度。
- 学习结果会沉淀为知识卡片、实验、测试、Trace 和项目证据。
- 每个稳定模块都会形成可理解和可面试的两种视图。
- 后续更换模型、语言或框架时，已有心智仍然可以复用。

成本：

- 需要持续维护学习总纲和学习进度。
- 需要保证理解版和题目版同步，避免答案与机制脱节。
- 需要为关键机制设计独立实验，短期产出速度可能低于直接套框架。
- 需要明确阶段验收，否则四条学习线可能同时扩张。

## 暂不决定

- 具体学习排期。
- 主实验语言。
- 主框架。
- 贯穿项目选题。
- 每个模块的资料清单。
- 阶段评测方式。

这些内容将在后续讨论中分别形成新的 ADR 或学习计划。
