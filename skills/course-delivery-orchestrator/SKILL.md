# 课程授课、复习与验收

## 目标

把稳定课程大纲编译为：

```text
真正能理解的推导
  +
真实可复现的实验
  +
可以定位的失败
  +
结构化面试表达
  +
可续接的掌握证据
```

## 五层职责

开始前必须区分：

| 层次 | 唯一职责 |
|---|---|
| 知识总纲 | 定义完整知识边界和稳定结论 |
| 课程目录 | 定义课号、认知顺序、案例、题目和验收 |
| 授课单元 | 根据问题完整性与知识密度，编译一个或多个相邻课程 |
| 学习文档 | 使用总分总结构讲清问题、机制、实验和面试答案 |
| 学习进度 | 按原课程和真实证据记录掌握状态 |

禁止把课程目录中的字段顺序直接复制成学习文章目录。

发生冲突时遵循：

```text
知识定义       → 知识总纲
覆盖与顺序     → 课程目录
文章组织       → 本 Skill 的授课合同
掌握状态       → 学习进度与真实证据
```

## 输入识别

进入课程仓库后依次读取：

1. 仓库规则和文件修改权限。
2. 课程目录。
3. 单课合同或课程模板。
4. 对应知识总纲或理解版正文。
5. 学习进度和已有课件。
6. 目标面试题的完整题目与追问。

只有题目编号时，必须回到题库读取题目原文；不得要求学习者根据编号猜题。

## 授课单元编译

### 默认保持单课

一节课程能够同时形成完整问题、机制推导、案例、正常实验、失败实验和面试回答时，按单课执行。

### 主动合并相邻课程

同时满足以下条件时，可以将相邻课程编译成一个授课单元：

1. 共同回答同一中心问题或连续追问链。
2. 单独讲授会沦为术语介绍、接口清单或低密度短文。
3. 能使用同一个案例、状态和实验逐步推进。
4. 合并后仍能画出一条清晰主线，认知负担可控。
5. 每个原课程的知识、题目和掌握证据仍能独立映射。

合并只改变实际授课单元，不擅自删除、改号或改变课程目录中的知识归属。

合并前输出：

```text
覆盖课程：
中心问题：
合并理由：
原课程 → 本单元章节 → 面试题 → 实验证据：
```

知识密度判断和合并细节见[互动授课流程](references/interactive-delivery.md)。

## 两种授课模式

### 连续引导授课

默认模式。适用于“开始上课”“产出学习文档”“先整体讲完”。

- 完整讲完当前授课单元。
- 思考问题用于制造认知冲突，提出后直接继续推导。
- 不频繁等待学习者作答。
- 结尾统一安排复述、画图、排障和面试巩固。

### 互动诊断授课

适用于“考考我”“一步步教我”“根据我的回答调整”。

- 一次只推进一个核心问题。
- 等待学习者作答后再决定加速、换例子或下钻。
- 不用“懂了吗”代替诊断。

用户明确选择的节奏优先于默认模式。

## 总分总授课合同

### 总：先展示要解决的问题

开头必须展示：

1. 当前授课单元与覆盖课程。
2. 本单元中心问题。
3. 目标面试题的编号和完整题目原文。
4. 题目之间的关系图。
5. 学完后应该形成的结构化答案骨架。
6. 本单元不展开的边界。

目标题目不能只展示编号。

### 分：按问题自然推导

正文组织为两到四个问题章节，不按课程目录字段机械分节。每个问题章节依次包含：

```text
本章问题
  ↓
直觉答案或常见误区
  ↓
制造认知冲突的反例
  ↓
具体输入、状态或数据
  ↓
ASCII 图
  ↓
逐步机制推导
  ↓
正常实验
  ↓
失败实验
  ↓
局部结论
  ↓
回答了哪道面试题的哪一部分
```

思考引导必须推动下一步推导，例如：

```text
如果 Temperature=0 就可靠，
为什么模型仍可能稳定地输出错误答案？
```

提出问题后必须用案例、数据、图或实验回答，不能只留下反问。

### 总：回到结构化面试答案

结尾逐题回收开头所有目标题：

1. 题目原文。
2. 一句话核心判断。
3. 30 秒直接回答。
4. 3 分钟完整回答。
5. 一张可以现场手画的 ASCII 图。
6. 原理、工程、项目三层追问。
7. 隐藏前提和适用边界。
8. 对应代码、Trace、测试或真实实验。

最后输出覆盖检查：

| 面试题 | 是否完整回答 | 正文依据 | 实验证据 | 仍缺什么 |
|---|---|---|---|---|

详细模板见[产物与状态合同](references/artifact-contract.md)。

## ASCII 图规则

图不是装饰。每张图必须：

1. 使用问题作为图标题。
2. 一张图只回答一个问题。
3. 优先控制在 5 至 9 个关键节点。
4. 标明数据、控制权、状态或验证关系。
5. 正常链路与失败链路分开画，避免所有信息塞进一张图。
6. 图后给出两到三条关键读图结论，不逐箭头复述。

抽象概念先画图和推演具体数据，再展示代码或框架。

## 案例与实验

使用一个贯穿授课单元的真实案例。案例必须具备：

```text
用户目标
已有输入
当前状态
可用能力
权限或资源边界
预期输出
真实副作用
成功标准
```

框架只作为机制实验载体，不按品牌组织正文。每次引入框架都要回答：

```text
上一阶段暴露了什么失败？
这个框架具体封装了哪个机制？
加入后解决了什么？
仍然没有解决什么？
```

正常实验必须展示真实输入、请求、状态、输出和确定证据。

失败实验必须完成：

```text
失败表象
  ↓
候选故障层
  ↓
最先检查的证据
  ↓
真实根因
  ↓
最小修复
  ↓
回归验证
```

## 面试与理解标准

面试导向不是先给背诵答案。完整顺序是：

```text
问题原文
  ↓
机制推导
  ↓
案例与实验
  ↓
失败与边界
  ↓
结构化口语回答
```

若学习者能背答案但无法画图、解释新案例或根据陌生 Trace 排障，视为未掌握。

较难英文第一次出现时使用`英文(精简通俗注释)`。

## 续课与复习

续课时读取已有课件、授课单元覆盖范围和学习进度，不依赖会话记忆猜测。

可执行：

```bash
python3 "${CODEX_HOME:-$HOME/.codex}/skills/course-delivery-orchestrator/scripts/course_state.py" \
  <课程目录> --lessons-dir <课件目录>
```

复习和验收时：

- 不先展示答案。
- 优先抽取曾经答错、实验失败或尚未形成证据的内容。
- 混合使用复述、画图、陌生 Trace、最小实现和连续追问。
- “听懂”“看过”“能跟着做”不能单独证明掌握。

详细评分见[验收与复习](references/assessment-and-review.md)。

## 课件与进度

仅在获得文件修改授权后写入课件和进度。

状态使用：

```text
课程状态：进行中
课程状态：待复核
课程状态：已通过
```

合并授课单元必须在课件中记录覆盖的原课程编号，并将证据分别映射回原课程。

交付前可执行：

```bash
python3 "${CODEX_HOME:-$HOME/.codex}/skills/course-delivery-orchestrator/scripts/validate_lesson.py" \
  <课件文件> --catalog <课程目录> --strict
```

## 完课条件

只有同时满足下列条件才标记已通过：

- 不看资料说清中心问题、机制和系统位置。
- 能独立画出关键调用链、状态或边界。
- 完成正常实验并用确定证据验收。
- 完成失败实验、定位根因并回归。
- 能说明什么时候不用该机制。
- 能逐题完成 30 秒回答并接住连续追问。
- 更换案例或框架后仍能识别同一机制。

## 资源读取规则

- 开始、继续、合并或恢复授课单元时读取[互动授课流程](references/interactive-delivery.md)。
- 创建正式课件或更新状态时读取[产物与状态合同](references/artifact-contract.md)。
- 设计复习、抽查、面试模拟或完课判断时读取[验收与复习](references/assessment-and-review.md)。

## 禁止事项

- 不把课程目录直接写成文章目录。
- 不只展示题目编号而隐藏题目原文。
- 不为了互动频繁打断连续学习。
- 不提出思考题后不继续推导答案。
- 不把 ASCII 图当作文字列表的换行版。
- 不将框架功能清单当成知识主干。
- 不因合并授课而删除原课程的覆盖和进度映射。
- 不在没有真实证据时更新为“已通过”。
