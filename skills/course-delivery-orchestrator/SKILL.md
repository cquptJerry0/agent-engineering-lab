# 链路课程授课与面试训练

## 目标

把稳定知识图和动态学习状态编译成当前一个 CU(Course Unit，课程单元)：

```text
知识总纲 + 学习进度 + 当前目标 + 题库
  ↓
动态选择当前 CU
  ↓
推导式理解
  ↓ 理解稳定
面试训练
  ↓ 真实验收
更新学习进度
```

## 五层职责

| 层次 | 唯一职责 |
|---|---|
| 知识总纲 | 定义完整知识边界、依赖和掌握标准 |
| 学习进度 | 记录状态、薄弱点和真实证据 |
| 当前 CU | 声明本次选课依据、覆盖范围和完成标准 |
| 推导式理解 | 按项目问题链组织，负责真正学懂 |
| 面试训练 | 按完整题目组织，负责可上场表达 |

课程不是第二份知识总纲。题库不是课程顺序。文档存在不代表学习完成。

## 开始前读取

进入课程仓库后读取：

1. 适用的仓库规则和文件修改权限。
2. 知识总纲及掌握要求。
3. 学习进度、薄弱点和最近证据。
4. 当前项目、面试目标和可用实验环境。
5. 题库中的完整问题和追问。
6. 已生成的 CU 及双轨完成状态。

如果已经存在未完成 CU，默认先续接；只有当前目标或前置条件明显变化时才重新选课。

## 动态选择当前 CU

读取[授课编译与双模式流程](references/interactive-delivery.md)。

优先选择：

1. 当前项目或面试立即需要但理解不足的机制。
2. 阻塞多个后续知识点的前置机制。
3. 曾答错、实验失败或只能背诵的知识点。
4. 长时间未复核的知识点。
5. 其他未开始知识点。

合并知识点前必须证明：

```text
共同中心问题
  +
同一贯穿案例
  +
连续输入与状态
  +
前后机制存在因果
  +
共享实验和 Trace
```

不预先承诺固定课数。CU 编号只表示实际生成顺序。

## 第一轨：链路学习

第一轨使用一个长期项目或案例，让同一系统持续演进：

```text
已有能力
  ↓
在真实任务中暴露问题
  ↓
现有机制为什么不够
  ↓
引入一个新机制
  ↓
输入、状态、控制权或输出发生变化
  ↓
正常与失败证据
  ↓
留下下一问题
```

### 先总后分再总

```text
总：完整推导链、选课依据和案例初始状态
  ↓
分：按问题演进展开系统版本
  ↓
总：边界、自测、知识图谱和面试题索引
```

章节必须按机制和状态变化组织，不能按题目编号、教材页码或框架功能组织。

### 标题与问题分层

理解轨的标题必须是可检索、可迁移的技术主题：

```text
CU 标题：模型生成、结构化输出与 Tool Calling 原理
阶段标题：模型 API 请求响应协议
阶段标题：工具执行控制与结果回填
```

标题回答`学什么技术`。每阶段内部的`当前问题`与`推导过程`回答`为什么需要、现有机制哪里不够、怎样演进`。

禁止把下面这类问句用作理解轨的 CU 或阶段标题：

```text
模型为什么只能生成候选答案
一次工具调用怎样演进成 Agent Loop
校验和回填怎样形成最小闭环
```

问句只用于第二轨面试题、自测题或阶段内部的认知冲突。

### 每个阶段回答

每个阶段必须使用五段结构：

```text
本阶段知识点群
  ↓
当前问题与推导过程
  ↓
机制全解
  ↓
状态变化
  ↓
阶段结论与下一问题
```

- `本阶段知识点群`列出知识点、作用和前后依赖，让学习者先知道这一大段在学什么。
- `推导过程`从案例问题推导出机制，回答为什么需要。
- `机制全解`系统解释定义、组成、运行顺序、概念边界、失败和适用条件。
- `状态变化`对照进入阶段前后的输入、状态、控制权、输出和未解决问题。
- `阶段结论`压缩当前心智，并明确下一阶段为什么出现。

不能因为推导已经讲过，就省略全面知识解释。

### 案例连续性

贯穿案例至少包含：

```text
用户目标
已有输入
当前状态
可用能力
权限和资源边界
预期输出
真实副作用
成功标准
```

切换案例必须说明原案例为什么无法承载新机制。

### 实验任务卡

每个实验必须写清：

```text
实验目标
覆盖知识点
为什么做
准备条件
输入与初始状态
操作步骤
预期现象
程序断言或人工检查
失败时先看什么
通过标准
产出证据
未证明部分
```

涉及代码、API 或工具时，至少提供请求样例、伪代码或可运行命令之一。

### 自测与知识关系图

- 自测题必须同时提供参考答案、判分点和常见误区。
- 知识关系图使用中文节点，箭头标明真实关系。
- 图后必须说明阅读顺序和关键结论。
- 英文术语列表不能代替知识图。

第一轨末尾只保留完整面试题索引和对应推导章节，不展开 30 秒回答、完整回答和追问。

## 第二轨：面试学习

只有第一轨结论稳定后，才生成独立`面试训练.md`。

每道题按下面顺序学习：

```text
完整题目
  ↓
一句话核心判断
  ↓
启发式思考
  ↓
30 秒回答
  ↓
完整回答
  ↓
原理、工程和项目追问
  ↓
实验、Trace、代码或真实请求证据
```

启发式思考至少回答：

| 思考 | 目标 |
|---|---|
| 没有它会怎样 | 找到真实问题 |
| 最小机制是什么 | 说明工作原理 |
| 工程收益是什么 | 说明为什么值得引入 |
| 边界和代价是什么 | 防止口号化 |

每道题必须回链第一轨。更换问法后仍应能从同一机制现场推导，而不是匹配背诵模板。

完整合同见[双轨产物与状态合同](references/artifact-contract.md)。

## 授课模式

### 连续引导

默认模式。思考题用于制造认知冲突，提出后直接继续推导，不频繁等待用户回答。

### 互动诊断

用户要求“一步步教”“考考我”时，一次只推进一个问题，根据回答决定加速、换例子或下钻。

两种模式都必须保持同一推导链和案例状态。

## 状态与续接

CU 状态只记录交付阶段：

```text
未开始 → 推导中 → 面试训练中 → 待复核 → 已通过
```

知识点进度记录掌握证据：

```text
未开始 → 已理解 → 已实验 → 已整合 → 已复核
```

两者不能混用。生成双轨文档后，知识点状态仍为未开始。

查看当前 CU：

```bash
python3 "${CODEX_HOME:-$HOME/.codex}/skills/course-delivery-orchestrator/scripts/course_state.py" \
  <课程目录>
```

校验双轨产物：

```bash
python3 "${CODEX_HOME:-$HOME/.codex}/skills/course-delivery-orchestrator/scripts/validate_lesson.py" \
  <推导式理解.md> \
  --interview <面试训练.md> \
  --outline <学习总纲.md> \
  --progress <学习进度.md> \
  --strict
```

详细掌握标准见[验收与复习](references/assessment-and-review.md)。

## 禁止事项

- 不把总纲顺序直接复制成固定课表。
- 不为保持课号制造低密度短课。
- 不把互不相关的知识点塞进同一 CU。
- 不按面试题顺序组织推导式理解。
- 不把理解轨的 CU 或阶段标题写成`为什么`、`怎样`、`如何`类问句。
- 不把完整面试答案塞回第一轨。
- 不让第二轨重新定义知识。
- 不提出思考题后留下假互动。
- 不把框架功能清单当成机制主线。
- 不用课程文件存在证明已经掌握。
