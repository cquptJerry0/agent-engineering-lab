# 课程授课、复习与验收

## 目标

把课程目录编译成：

```text
少而完整的高密度课程
  +
按机制推导的学习正文
  +
按题拆分的面试答案
  +
真实实验和失败证据
  +
可续接的学习状态
```

## 不可混淆的六层职责

| 层次 | 唯一职责 |
|---|---|
| 知识总纲 | 定义知识边界和稳定结论 |
| 课程目录 | 记录覆盖条目、认知顺序、案例、题目和验收 |
| 实际课程 | 按合理知识密度合并相邻目录条目 |
| 推导式理解文档 | 按知识机制组织，负责真正学懂 |
| 最终面试答案文档 | 按一道题一节组织，负责可上场表达 |
| 学习进度 | 按原目录条目和真实证据记录状态 |

必须牢记：

```text
课程目录中的 30 个条目
不等于必须上 30 节实际课程

一节实际课程
= 一个完整知识域
= 一条可以连续推导的机制主线
= 一份推导式理解文档
```

禁止把课程目录字段直接复制成文章目录，也禁止把完整面试答案塞回推导式理解文档。

发生冲突时遵循：

```text
知识定义       → 知识总纲
覆盖与顺序     → 课程目录
实际课数       → 知识密度与认知闭环
学习结构       → 推导式理解文档合同
面试结构       → 最终答案文档合同
掌握状态       → 学习进度与真实证据
```

## 开始前读取

进入课程仓库后依次读取：

1. 仓库规则和文件修改权限。
2. 课程目录及相邻条目。
3. 对应知识总纲或理解版正文。
4. 学习进度和已有学习文档。
5. 目标题库中的完整题目和追问。
6. 可用实验环境。

只有题目编号时，必须回到题库读取题目原文。

## 实际课程编译

### 优先组织合理知识密度

不要默认一个目录条目就是一节课。先判断这个知识域能否形成：

```text
共同起点
  ↓
连续问题
  ↓
机制逐步演进
  ↓
统一案例
  ↓
正常与失败实验
  ↓
一组强相关面试题
```

如果可以，就合并为一节实际课程和一份推导式理解文档。

### 必须合并的信号

- 单个条目只能讲定义、参数或接口。
- 单个条目无法独立形成正常与失败实验。
- 多个相邻条目共同回答同一条连续追问链。
- 多个条目使用同一案例和状态，只是被课号机械切断。
- 拆开后每篇正文知识密度过低，需要重复前置背景。

### 必须拆开的信号

- 已经出现两个无法用一句话统一的中心问题。
- 需要不同案例、状态模型或实验环境。
- 合并后知识图无法在一张总图中清晰表达。
- 学习者必须先独立掌握前半部分，才能理解后半部分。
- 一次课程无法完成理解、实验和复述。

合并只改变实际课程数量，不删除原目录条目。合并前输出：

```text
实际课程标题：
覆盖目录条目：
核心推导链：
合并理由：
原条目 → 学习章节 → 面试题 → 实验证据：
```

详细判断见[授课编译与双模式流程](references/interactive-delivery.md)。

## 双轨产物合同

每节实际课程对应两条严格分离的产物轨道。

### 轨道一：推导式理解文档

职责是学懂一个完整知识域。采用总分总：

```text
总：核心推导链与完整问题全景
  ↓
分：按知识机制和问题演进展开
  ↓
总：口语化输出模板、自测问题、知识图谱
```

正文按机制组织，不按面试题逐题组织。每个机制章节优先回答：

```text
没有它会怎样？
为什么会出现这个问题？
最小机制是什么？
数据、状态和控制权怎样变化？
正常实验证明了什么？
失败实验暴露了什么？
边界和代价是什么？
它怎样自然引出下一机制？
```

正式结构见[双轨产物与状态合同](references/artifact-contract.md)。

### 轨道二：最终面试答案文档

职责是把已经理解的知识拆成独立题目。每道题单独组织：

```text
题目与题型
教科书定义
启发式思维表
口语化输出
必要的 ASCII 图或表
原理、工程和项目追问
实验或 Trace 证据
对应推导式理解文档
```

启发式思维至少回答：

| 问题 | 回答目标 |
|---|---|
| 没有它会怎样 | 找到真实问题 |
| 怎么解决 | 说明最小机制 |
| 好处 | 说明工程收益 |
| 坏处或边界 | 说明代价和适用条件 |

最终答案文档不能反向定义知识，只能压缩推导式理解文档中的稳定结论。

### 章节级聚合

完成多个实际课程后，可以继续生成：

```text
面试输出手册：跨课程聚合所有独立答案
思维导图：一道题一个节点，保留金句、机制和追问
```

聚合文档只负责复习和检索，不代替两条主轨。

## 两种授课模式

### 连续引导授课

默认模式。适用于“开始上课”“先完整讲完”“产出推导式理解”。

- 连续完成当前推导式理解文档。
- 思考问题用于制造认知冲突，提出后直接继续推导。
- 不频繁等待学习者作答。
- 学习文档完成后，再集中巩固和拆分面试题。

### 互动诊断授课

适用于“考考我”“一步步教我”“按我的回答调整”。

- 一次推进一个机制问题。
- 等待回答后再决定加速、换例子或下钻。
- 不用“懂了吗”代替诊断。

用户明确选择的节奏优先。

## 推导式理解规则

### 思考必须推动知识产生

优先使用反例、预测、取舍和排障：

```text
如果 Temperature=0 就可靠，
为什么模型仍可能稳定地输出错误答案？
```

提出后必须紧接：

```text
具体输入
  ↓
直觉推演
  ↓
反例
  ↓
机制解释
  ↓
实验验证
  ↓
局部结论
```

不能只留下问题，也不能用“你觉得呢”制造假互动。

### ASCII 图和表

正文以思考、ASCII 图和表为主要表达手段。

每张图必须：

1. 只回答一个明确问题。
2. 标明组件、数据、状态、控制权或验证关系。
3. 优先控制在 5 至 9 个关键节点。
4. 正常链路和失败链路分开画。
5. 图后给出两到三条关键结论。

表格优先用于：

- 相邻机制对比。
- 输入、状态和输出对照。
- 方案收益、代价和边界。
- 失败表象与故障层映射。

### 案例与实验

一节实际课程使用一个贯穿案例：

```text
用户目标
已有输入
当前状态
可用能力
权限或资源边界
预期输出
真实副作用
成功标准
```

框架只作为机制实验载体。每次引入框架都要回答：

```text
上一阶段暴露了什么问题？
框架封装了什么机制？
加入后解决了什么？
仍然没有解决什么？
```

正常实验记录：

```text
假设
真实输入
操作
观察点
断言或环境结果
结论
未证明部分
```

失败实验完成：

```text
失败表象
  ↓
候选故障层
  ↓
最先检查的证据
  ↓
真实根因
  ↓
最小修复
  ↓
回归验证
```

## 面试题拆分规则

推导式理解文档末尾只保留：

1. 简洁的口语化输出模板。
2. 完整面试题目清单。
3. 每道题对应的知识章节。

完整的 30 秒、3 分钟、连续追问和项目证据必须写入独立最终答案文档。

面试题拆分顺序：

```text
推导式理解已经稳定
  ↓
抽取完整问题
  ↓
合并同义问法
  ↓
按一道题一节生成最终答案
  ↓
回链学习章节和实验证据
  ↓
聚合进面试输出手册与思维导图
```

较难英文第一次出现时使用`英文(精简通俗注释)`。

## 续课、状态与验收

续课只以推导式理解文档作为当前实际课程的主状态载体。最终答案文档记录题目完成度，不替代学习状态。

可执行：

```bash
python3 "${CODEX_HOME:-$HOME/.codex}/skills/course-delivery-orchestrator/scripts/course_state.py" \
  <课程目录> --lessons-dir <推导式理解文档目录>
```

讲解完成最多证明已理解；正常与失败实验均有证据后才进入待复核；间隔复习、陌生案例迁移和面试连续追问通过后才标记已通过。

正式交付时执行：

```bash
python3 "${CODEX_HOME:-$HOME/.codex}/skills/course-delivery-orchestrator/scripts/validate_lesson.py" \
  <推导式理解文档> \
  --interview <最终答案文档> \
  --catalog <课程目录> \
  --strict
```

详细评分见[验收与复习](references/assessment-and-review.md)。

## 禁止事项

- 不把目录条目数量当成实际课程数量。
- 不为保持原课号而制造低密度短课。
- 不把课程目录直接写成学习正文。
- 不按面试题顺序组织推导式理解正文。
- 不把完整面试答案塞回推导式理解文档。
- 不只展示题目编号而隐藏题目原文。
- 不提出思考题后不继续推导答案。
- 不把框架功能清单当成知识主干。
- 不因合并实际课程而删除原条目的覆盖和进度映射。
- 不在没有真实证据时更新为已通过。
