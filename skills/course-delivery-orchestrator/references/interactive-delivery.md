## 1. 开课准备

读取：

- 当前及相邻课程目录条目。
- 对应知识总纲。
- 完整面试题和追问。
- 已有推导式理解文档和最终答案文档。
- 学习进度。
- 可用实验环境。

先确定实际课程边界：

```text
实际课程标题：
覆盖目录条目：
共同起点：
核心推导链：
贯穿案例：
正常与失败实验：
面试题集合：
本课不展开：
```

## 2. 实际课程密度

### 合理密度的判断

一节实际课程应该满足：

| 维度 | 要求 |
|---|---|
| 中心问题 | 一句话可以说清 |
| 知识主线 | 多个机制存在自然因果或演进关系 |
| 案例 | 可以共享同一输入、状态和目标 |
| 实验 | 可以逐步增加机制并主动制造失败 |
| 表达 | 能形成一组强相关面试题 |
| 认知负担 | 一次学习可以完整理解和复述 |

### 优先合并

```text
目录条目 A：只解释模型生成
目录条目 B：只解释请求响应
目录条目 C：只解释工具协议
        ↓
如果三者共同回答：
“自然语言怎样变成可执行、可验证的 Agent 行动？”
        ↓
合并为一节实际课程
        ↓
只产出一份推导式理解文档
```

### 必须拆分

出现两个独立状态模型、两套实验环境或两条无法统一的推导链时拆分。

课程合并后保留映射：

| 原目录条目 | 推导式理解章节 | 面试题 | 实验证据 |
|---|---|---|---|

## 3. 推导式理解编译

学习正文按知识机制组织。

### 总：核心推导链

先从一个真实起点连续提出问题：

```text
已有能力
  ↓
暴露问题
  ↓
需要新机制
  ↓
新机制解决问题
  ↓
产生新的边界
  ↓
自然引出下一机制
```

再画完整知识全景，让学习者先知道整节课在解决什么。

### 分：机制章节

每个章节按实际理解需要选择下列内容，不机械复制字段：

```text
为什么需要
问题如何出现
最小机制
ASCII 图
具体数据或协议
对比表
正常实验
失败实验
边界和代价
与下一机制的关系
```

章节标题应描述知识机制，例如：

```text
一、模型怎样从上下文生成下一个 Token
二、真实 API 怎样承载文本、事件与结束状态
三、工具请求怎样经过校验、执行和结果回填
```

不得写成：

```text
一、AGENT-MODEL-001
二、AGENT-MODEL-002
```

### 总：学习收束

推导式理解文档末尾统一包含：

```text
口语化输出模板
自测问题
知识图谱
面试题拆分清单
```

口语化输出模板只做简洁复述，不展开完整面试攻防。

## 4. 面试答案拆分

推导式理解稳定后再生成独立最终答案文档。

每道题使用：

```text
题目
题型
教科书定义
启发式思维表
口语化输出
必要的图或表
追问点
实验或 Trace 证据
对应学习章节
```

题目必须使用完整原文，同义问法合并为追问，不建立重复答案。

章节或知识域完成后，可以把独立答案继续聚合到：

- 面试输出手册。
- 一道题一个节点的思维导图。

## 5. 两种授课模式

### 连续引导授课

默认模式：

```text
核心推导链
  ↓
连续讲完机制正文
  ↓
正常与失败实验
  ↓
口语化模板、自测和知识图谱
  ↓
集中拆分最终面试答案
```

思考点用于制造认知冲突，提出后直接继续推导。

### 互动诊断授课

一次只推进一个机制问题：

```text
给出具体输入
  ↓
让学习者预测
  ↓
判断当前心智
  ↓
用图、数据或实验补齐
  ↓
换一个案例验证迁移
```

## 6. 中断恢复

恢复时回答：

```text
当前实际课程覆盖哪些目录条目？
推导式理解完成到哪个机制章节？
哪些正常和失败实验已有证据？
口语化模板、自测和知识图谱是否完成？
哪些面试题已经拆成最终答案？
下一步最小动作是什么？
```

主学习状态以推导式理解文档为准，面试答案完成度单独记录。
