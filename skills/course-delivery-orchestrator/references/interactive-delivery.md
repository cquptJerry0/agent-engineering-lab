# 动态选课与链路授课

## 1. 开课准备

读取：

- 知识总纲。
- 学习进度和薄弱点。
- 当前项目或面试目标。
- 完整题目和追问。
- 已有 CU 与证据。
- 可用实验环境。

先输出 CU 设计卡：

```text
CU 标题：
中心问题：
选课依据：
覆盖知识点：
前置能力：
贯穿案例：
核心推导链：
正常与失败证据：
面试题集合：
完成标准：
本次不展开：
```

## 2. 动态选择

若存在未完成 CU：

```text
目标未变化且前置仍成立
  → 继续当前 CU

目标明显变化或前置缺失
  → 说明原因后重新编译
```

若没有当前 CU：

```text
找最高优先级薄弱点
  ↓
补齐必要前置
  ↓
寻找共享问题和案例的知识点
  ↓
形成一个可验收闭环
```

## 3. 链路密度

合理 CU 满足：

| 维度 | 要求 |
|---|---|
| 中心问题 | 一句话说清 |
| 因果链 | 前一机制自然引出后一机制 |
| 案例 | 同一用户目标、输入和环境 |
| 状态 | 可以观察连续变化 |
| 实验 | 能制造正常和失败证据 |
| 面试 | 题目属于同一机制簇 |
| 负担 | 一次学习可以复述和验证 |

知识点少但只能讲术语时应继续合并。知识点多但仍共享一条状态链时不必机械拆分。

## 4. 连续引导模式

```text
完整推导链
  ↓
案例初始状态
  ↓
版本逐步演进
  ↓
正常与失败实验
  ↓
边界、自测和知识图谱
  ↓
独立面试训练
```

思考题提出后直接用具体输入、反例和机制继续推导。

## 5. 互动诊断模式

```text
给出具体输入
  ↓
让学习者预测
  ↓
根据回答定位心智
  ↓
用图、状态或实验补齐
  ↓
换一个案例验证迁移
```

一次只推进一个问题，但不要改变总体推导链。

## 6. 中断恢复

恢复时回答：

```text
当前 CU 的中心问题是什么？
已经推进到哪个系统版本？
哪些知识点已有理解证据？
哪些正常和失败实验已有结果？
面试训练完成了哪些题？
下一步最小动作是什么？
```

不要通过固定课号猜进度。
