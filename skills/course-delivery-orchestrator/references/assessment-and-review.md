# 验收与复习

## 1. 掌握维度

| 维度 | 证明方式 |
|---|---|
| 定位 | 说明知识点解决的问题和系统位置 |
| 推导 | 从已有能力连续推出新机制 |
| 状态 | 画出输入、状态、控制权和输出 |
| 实现 | 完成最小正常实验 |
| 排障 | 根据陌生失败证据定位根因 |
| 边界 | 说明什么时候不用该机制 |
| 表达 | 完成核心判断、30 秒和完整回答 |
| 迁移 | 更换框架、案例或问法后仍能识别机制 |

第一轨还要单独检查：

| 维度 | 证明方式 |
|---|---|
| 知识定位 | 能指出每个阶段覆盖的知识点群 |
| 全面解释 | 脱离案例后仍能系统解释机制 |
| 实验理解 | 能说清每一步在验证哪个结论 |
| 自测闭环 | 能对照判分点发现自己的缺口 |
| 图谱理解 | 能按关系箭头重新讲出整条链 |

## 2. CU 完成门禁

```text
未开始
推导中
面试训练中
待复核
已通过
```

`待复核`表示当场可以独立完成推导、实验和面试表达，但还缺少间隔复习或陌生案例迁移。

`已通过`要求：

- 能独立复述完整问题链。
- 正常和失败实验都有证据。
- 能分析未见过的变体。
- 能说明边界和替代方案。
- 面试追问能落到代码、Trace、指标或真实产物。

## 3. 面试验收

每道主问题至少追三层：

1. 原理：最小机制、协议和状态。
2. 工程：失败、安全、性能和演进。
3. 项目：真实做法、证据和取舍。

验收时刻意改变问法。若只能识别题库原句，说明仍在背诵。

## 4. 间隔复习

- 下一个 CU 开始前，用一个短问题回忆前置链路。
- 一个知识域结束后，做跨 CU Trace 排障和随机抽题。
- 学习周期较长时，约一周后重新画图或重做失败实验。
- 用户给出明确时间计划时，使用具体日期记录复核。

## 5. 薄弱点修复

| 表现 | 修复方式 |
|---|---|
| 只能背定义 | 回到“没有它会怎样”的案例 |
| 推导中间断裂 | 缩小 CU 或补前置机制 |
| 图画不出来 | 重放输入、状态和控制权 |
| 正常 Demo 会做但不会排障 | 增加失败注入和证据定位 |
| 面试回答空泛 | 强制加入边界和真实证据 |
| 换问法不会 | 从第一轨机制重新推导 |
