## 1. 运行模型

```text
稳定知识图
  学习总纲 + 题库 + 资料

动态学习状态
  进度 + 薄弱点 + 当前目标

生成视图
  当前 CU
```

CU 规划的核心不是把知识图切成固定课号，而是根据状态寻找当前最有价值的完整问题。该方法不依赖 Agent 领域，同样适用于框架原理、数据库、分布式系统、操作系统、编译器、网络协议和算法体系。

## 2. 当前 CU 选择

建立候选表：

| 知识点 | 当前状态 | 前置依赖 | 当前价值 | 证据缺口 |
|---|---|---|---|---|

选择时先回答：

1. 哪个问题正在阻塞后续理解或当前任务？
2. 学习者已经具备哪些能力？
3. 哪些知识点可以在同一个案例中连续出现？
4. 本次结束后能产出什么可验证证据？

CU 设计卡：

```text
CU 标题：
中心问题：
选课依据：
覆盖知识点：
前置能力：
贯穿案例：
核心推导链：
正常与失败证据：
面试目标：
完成标准：
本次不展开：
```

## 3. 知识聚合与拆分

适合合并：

- 共享同一真实问题和执行链、请求链或问题演进链。
- 前一机制的边界自然要求后一机制。
- 可以复用同一输入、状态和实验。
- 面试追问属于同一条因果链。

需要拆分：

- 两个中心问题无法用一句话统一。
- 需要不同用户目标、状态模型或环境。
- 其中一部分必须先独立掌握。
- 一次学习无法完成复述、实验和追问。

知识点数量不是拆分标准。一个 CU 可以有 3 个或 12 个知识点，只要链路连续且认知负担可控。

## 4. 贯穿案例

案例卡：

```text
用户目标：
已有输入：
初始状态：
可用能力：
约束和资源边界：
预期输出：
副作用或复杂度代价：
成功标准：
```

根据技术对象调整状态维度：

| 技术对象 | 贯穿载体 | 优先追踪的变化 |
|---|---|---|
| 运行时或框架 | 一个持续演进的应用或执行任务 | 输入、调度状态、控制权、输出 |
| 算法或数据结构 | 一个规模逐步增长的问题实例 | 不变量、步骤、复杂度、退化条件 |
| 数据库或分布式系统 | 一条真实请求、事务或复制链 | 参与者、消息、状态、一致性、失败恢复 |
| 协议或基础设施 | 一个端到端连接、部署或调度案例 | 阶段、资源、控制面、数据面、故障 |

案例不要求一定存在外部工具或真实副作用，但必须存在可观察状态、因果关系和可验证结果。

案例按版本增长：

```text
V0 已有能力
  ↓ 暴露问题
V1 引入机制 A
  ↓ 暴露问题
V2 引入机制 B
  ↓ 暴露问题
V3 形成当前闭环
```

每一版都记录：

- 新输入。
- 新状态或不变量。
- 控制过程变化。
- 可观察输出。
- 正常证据。
- 失败证据。
- 尚未解决的问题。

## 5. 双轨关系

```text
推导式理解
  按问题和机制组织
  ↓ 稳定结论
面试训练
  按完整题目组织
```

第一轨负责回答“为什么”和“怎样工作”；第二轨负责回答“怎样在不同问法下表达和防守”。

面试题可以来自题库，也可以从核心机制抽取，但每道题必须回链第一轨。题库不能反向扩大本次 CU 的知识边界。

## 6. 完整排期例外

完整排期只在外部约束真实存在时生成。

合格排期必须声明：

```text
这是当前条件下的暂定生成视图
生成时间：
目标人群：
固定约束：
依赖假设：
重排触发条件：
```

排期中的 CU 仍按中心问题组织，不按教材页数、文章来源或框架功能列表组织。
