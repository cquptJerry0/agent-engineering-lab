# 通用 100 分理想架构推演

## 推演顺序

不要从“现有代码还能加什么”开始，按下面顺序重建：

```text
业务增长或风险
  -> 新入口、新角色、新资源、新环境
  -> 系统冲突
  -> 理想分层
  -> 高级机制
  -> 迁移与验证
```

每个高级机制都要能回答：谁消费、边界在哪里、失败怎么办、如何观测、如何升级和如何回滚。

## 100 分能力地图

完成同类系统调研后，必须把项目从“现有实现”提升为“能力地图”，至少覆盖与业务冲突直接相关的设计面；平台、基础设施和跨域项目应继续展开到控制、执行、治理、观测和演进等多个面。使用下面的推演表，不允许直接从目录树跳到简历句子：

| 业务增长或风险 | 现状上限 | 规模放大后的系统冲突 | 100 分机制 | 上下游边界 | 验证与回滚 |
| --- | --- | --- | --- | --- | --- |
| 新入口 / 新角色 / 新资源 / 新环境 | 当前流程或实现的瓶颈 | 扩展、可靠性、权限、一致性、性能或演进冲突 | 理想控制面 / 执行面 / 数据面 / 观测面机制 | 谁消费、谁负责、契约是什么 | 如何验证、失败如何恢复、如何迁移 |

优化候选必须来自这张地图。对每个重要冲突至少提出三个机制方向，再按业务相关性、技术上限、实现可行性和面试解释深度筛选；“代码里没有”只能影响落点证据，不能作为删掉设计的理由。

## 设计面选择器

### 1. 领域流程与状态机

适用于审核、发布、入库、审批、任务流和多步骤交互。推演状态模型、状态转移约束、事件驱动、补偿、暂停恢复、人工介入和结果回查。

### 2. 契约、协议与版本

适用于开放接口、SDK、命令、组件库和跨团队复用。推演 Schema、类型系统、适配层、兼容矩阵、变更检测、迁移提示、契约测试和版本协商。

### 3. 控制面与治理

适用于多租户、多业务线、多角色、复杂权限和合规。推演身份、策略、资源授权、审批、审计、配额、限流、风险拦截、回收和策略版本。

### 4. 执行与可靠性

适用于批处理、异步任务、自动化、弱网和跨服务调用。推演状态化任务、幂等、检查点、重试、超时、并发控制、补偿、断点续跑和一致性回查。

### 5. 性能与规模

适用于高流量页面、大数据渲染、实时传输和频繁更新。推演资源模型、虚拟化、缓存、批处理、增量更新、调度、背压、降级、SLO 和成本模型。

### 6. 观测与验证

适用于线上排障、用户反馈、自动化结果和复杂链路。推演结构化日志、Trace、指标、错误分类、回放、采样、实验、评估集、告警和反馈闭环。

### 7. 平台演进与生态

适用于组件、SDK、工具、插件和多项目复用。推演扩展点、能力注册、按需加载、分发、自更新、灰度、回滚、废弃策略和采用规范。

## 高级机制生成器

对任意普通实现连续追问：

1. 规模放大十倍会先坏在哪里？
2. 入口从一个变成多个，哪些契约必须稳定？
3. 用户、角色、资源和环境如何隔离？
4. 请求或任务失败后如何确认是否已经生效？
5. 数据、状态和缓存如何保持一致？
6. 版本不一致时如何兼容、灰度和回滚？
7. 出现争议时如何审计、回放和证明？
8. 哪些环节可以从人工操作升级为编译期或运行时自动化？

每个问题至少产出一个高级机制，再按业务相关性、技术上限和简历密度筛选。最终故事数量随项目复杂度变化：简单项目保留少量主线，复杂平台可以围绕多个正交冲突展开，核心约束是每条都代表独立的系统能力。

## 不同业务的推演示例

```text
前端性能：事件速率 -> 状态更新放大 -> 调度/批处理 -> 空间窗口化 -> 性能基线
代码合规：依赖风险 -> 规则识别 -> 自动替换 -> 测试门禁 -> 持续治理
AI 自动化：任务目标 -> 工具契约 -> 受控执行 -> 结果验证 -> 人工兜底
开放平台：能力抽象 -> 稳定契约 -> 身份治理 -> 多入口执行 -> 版本演进
业务流程：用户目标 -> 状态模型 -> 规则校验 -> 异常恢复 -> 转化指标
监控 SDK：事件采集 -> 插件扩展 -> 可靠上报 -> 诊断回放 -> 采样成本控制
```

系统可以有控制面、执行面或契约面，但不要求所有项目都套同一套名词。先从业务冲突选设计面，再决定技术语言。
