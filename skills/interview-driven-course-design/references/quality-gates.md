# 自适应双轨课程质量门禁

## 1. 真相源门禁

- 是否明确知识总纲、学习进度、题库和资料各自职责？
- CU 是否只是当前生成视图？
- 课程是否复制了一套新的知识树？
- 生成课程是否错误地升级了学习状态？

## 2. 动态选课门禁

- 是否有当前目标和选课依据？
- 是否读取未掌握、薄弱点、遗忘或当前项目需求？
- 是否检查前置依赖？
- 是否默认只生成当前 CU？
- 若生成完整排期，是否说明外部约束、暂定性质和重排条件？

## 3. 聚合门禁

同一 CU 的知识点必须：

- 共同回答一个中心问题。
- 使用同一贯穿案例。
- 保持输入、状态和控制权连续。
- 形成因果推导链。
- 可以共享端到端 Trace 和实验。

删除任一中间机制后，后续推导仍能无损成立，则该机制可能只是并列百科内容。

## 4. 第一轨门禁

- 是否先给完整推导链和案例初始状态？
- CU 与阶段标题是否是可检索的名词化技术主题？
- `为什么`、`怎样`、`如何`类问题是否放在`当前问题`而不是理解轨标题？
- 每一阶段是否显式列出本阶段知识点群？
- 每一阶段是否同时包含推导过程和机制全解？
- 机制全解是否覆盖定义、组成、运行顺序、边界和失败？
- 每一阶段是否有输入、状态、控制权和输出的前后对照？
- 是否同时展示正常和失败链路？
- 每个实验是否说明目标、准备、步骤、预期现象、通过标准和证据？
- 自测是否同时提供参考答案、判分点和常见误区？
- 知识关系图是否使用中文节点、关系箭头和读图说明？
- 是否只保留面试题索引，没有混入完整面试答案？

## 5. 第二轨门禁

每道题是否包含：

- 完整题目和题型。
- 一句话核心判断。
- 启发式思考。
- 30 秒回答。
- 完整回答。
- 必要的图或表。
- 原理、工程和项目追问。
- 实验、Trace、代码或真实请求证据。
- 对应推导章节。

改变题目问法后若无法从同一机制作答，则不通过。

## 6. 通用性门禁

执行三次替换：

```text
替换框架
替换案例
替换题库
```

替换后核心问题、机制和验收仍应成立。若课程依赖品牌 API、固定课数或单一题库才能成立，必须重构。
