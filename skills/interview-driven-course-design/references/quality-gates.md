# 面试导向课程质量门禁

## 目录

1. 结构门禁
2. 完整性门禁
3. 单课门禁
4. 面试门禁
5. 通用性门禁
6. 最终审计

## 1. 结构门禁

- 是否区分知识总纲、课程目录、单课模板和学习进度？
- 是否只有一份文件拥有知识定义权？
- 课程是否先给全景，再按认知依赖推进？
- 课程编号是否连续且无重复？
- 是否避免提前生成大量空课件？

## 2. 完整性门禁

- 每个核心能力是否有课程主归属？
- 被合并的知识是否共享同一问题和实验？
- 支线是否有清晰触发条件？
- 删除或延后的内容是否有理由？
- 课程是否因追求短小而漏掉失败、安全或生产边界？

## 3. 单课门禁

每课必须有：

- 一个可以预测、取舍或排障的思考题。
- 一句话心智。
- 一个真实具体案例。
- 一张 ASCII 图。
- 一个正常实验。
- 一个失败实验。
- 一个明确完成标准。

出现下面情况视为不通过：

- 只有术语清单。
- 只有正常 Demo。
- 案例没有输入、状态和结果。
- ASCII 图只是装饰，没有控制权或数据流。
- 验收只能通过“听懂了”判断。

## 4. 面试门禁

- 是否存在 30 秒核心回答？
- 是否存在 3 分钟完整回答？
- 是否准备原理、工程和项目三层追问？
- 是否识别题目隐藏前提？
- 是否有代码、实验、指标、日志或产物作为证据？
- 是否能说明什么时候不用该方案？

面试答案若只能背诵，换一种问法就失效，则不通过。

## 5. 通用性门禁

进行三次替换测试：

```text
替换框架
替换案例
替换题库
```

替换后仍应保持：

- 核心问题成立。
- 机制解释成立。
- 实验可以迁移。
- 验收标准基本稳定。

如果课程依赖某个品牌 API、固定课数或单一题库才能成立，必须重构。
