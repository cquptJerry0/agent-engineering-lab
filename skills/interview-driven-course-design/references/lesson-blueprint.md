# 双轨课程单元蓝图

## 目录

1. CU 合同
2. 推导式理解
3. 面试训练
4. 实验与证据
5. 状态写回

## 1. CU 合同

```markdown
# CU-序号：标题

- 生成时间：
- 当前目标：
- 选课依据：
- 覆盖知识点：
- 前置能力：
- 中心问题：
- 贯穿案例：
- 完成标准：
- 失效或重排条件：
```

一个 CU 必须形成：

```text
连续问题链
  +
同一项目状态演进
  +
正常与失败证据
  +
独立面试训练
```

## 2. 推导式理解

推荐结构：

```markdown
# CU-序号：标题 - 推导式理解

> CU 状态：
> 生成依据：
> 覆盖知识点：

## 选课依据与覆盖知识点

## 核心推导链

## 贯穿案例与初始状态

## 阶段一：已有能力怎样暴露问题

## 阶段二：为什么需要新机制

## 阶段三：新机制怎样改变系统

## 正常链路与失败链路

## 最小实验

## 边界、代价与下一问题

## 自测问题

## 知识图谱

## 面试题索引
```

机制章节按实际问题调整，不机械复制模板，但每一阶段都要说明：

```text
上一状态
暴露问题
引入机制
状态变化
验证证据
下一问题
```

推导式理解只保留面试题目索引和一句定位，不展开完整答案。

推荐结构：

```markdown

> 对应推导式理解：

## 1. 完整题目？

30 秒回答：

> 可直接上场的短答。

完整回答：

ASCII 图或关键表：

追问：

- 原理追问：
- 工程追问：

对应推导章节：
```

第二轨按题组织，可以脱离第一轨直接用于模拟面试，但所有结论都必须能回链。

## 4. 实验与证据

正常实验：

```text
假设：
真实输入：
操作：
观察点：
断言：
结论：
未证明部分：
```

失败实验：

```text
失败表象
  ↓
候选故障层
  ↓
检查证据
  ↓
真实根因
  ↓
最小修复
  ↓
回归验证
```

## 5. 状态写回

```text
CU 生成
  → 不更新进度

独立复述通过
  → 已理解

正常与失败实验通过
  → 已实验

综合项目验证通过
  → 已整合

间隔复习和陌生案例迁移通过
  → 已复核
```

状态必须写回知识点主归属的进度文档，不在课程目录维护第二套长期状态。
