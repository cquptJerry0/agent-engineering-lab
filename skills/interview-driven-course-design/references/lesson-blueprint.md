## 1. CU 合同

```markdown
# CU-序号：名词化技术主题

- 生成时间：
- 当前目标：
- 选课依据：
- 覆盖知识点：
- 前置能力：
- 中心问题：
- 贯穿案例：
- 完成标准：
- 失效或重排条件：
```

一个 CU 必须形成：

```text
连续问题链
  +
同一项目状态演进
  +
正常与失败证据
  +
独立面试训练
```

```markdown
> 覆盖知识点：

## 选课依据与覆盖知识点

## 核心推导链

## 贯穿案例与初始状态

## 阶段一：核心技术主题 A

## 阶段二：核心技术主题 B

## 阶段三：核心技术主题 C

## 正常链路与失败链路

## 实验任务卡

## 边界、代价与下一问题

## 自测题与答案

## 知识关系图

## 面试题索引
```

CU 与阶段标题要像`React Fiber 原理`一样直接标识技术块。`为什么需要新机制`、`怎样改变系统`等内容放进`当前问题`与`推导过程`，不作为理解轨标题。

## 3. 阶段知识点群

每个阶段必须先声明它在讲哪些知识点：

```markdown
### 本阶段知识点群

| 知识点 | 本阶段解决的问题 | 与前后阶段的关系 |
|---|---|---|
```

然后按下面的职责展开：

```markdown
### 当前问题

### 推导过程

解释为什么现有能力不够，新机制如何被逼出来。

### 机制全解

系统解释本阶段每个知识点：

1. 准确定义。
2. 组成部分。
3. 运行顺序。
4. 输入、状态、控制权和输出。
5. 与相近概念的边界。
6. 常见失败和适用条件。

### 状态变化

| 维度 | 进入阶段前 | 引入机制后 |
|---|---|---|
| 输入 | | |
| 状态 | | |
| 控制权 | | |
| 输出 | | |
| 仍未解决 | | |

### 阶段结论

### 下一问题
```

推导负责建立因果，机制全解负责形成可检索知识。只有其中一个都不通过。

## 4. 实验任务卡

每个实验必须是学习者可以实际执行的任务卡：

```text
实验目标：
覆盖知识点：
为什么做：
准备条件：
输入与初始状态：
操作步骤：
预期现象：
程序断言或人工检查：
失败时先看什么：
通过标准：
产出证据：
这个实验没有证明什么：
```

只写“运行一次并观察”不算实验。涉及 API、工具或代码时，至少给出请求样例、伪代码、可运行命令中的一种。

## 5. 自测与知识关系图

自测不能只有问题。推荐：

```markdown
### 题目 1

问题：

参考答案：

判分点：

- 1 分：
- 1 分：

常见误区：
```

知识关系图必须：

- 使用中文节点，英文只作为括号内术语。
- 在箭头上写清“产生”“约束”“读取”“验证”“回填”等关系。
- 区分模型内部、程序控制和真实环境。
- 图后增加“如何读图”和三到五条关键结论。

## 7. 状态写回

```text
CU 生成
  → 不更新进度

独立复述通过
  → 已理解

正常与失败实验通过
  → 已实验

综合项目验证通过
  → 已整合

间隔复习和陌生案例迁移通过
  → 已复核
```

状态必须写回知识点主归属的进度文档，不在课程目录维护第二套长期状态。
