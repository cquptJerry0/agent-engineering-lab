## 1. 单课合同

一节课必须同时产生认知、实践和答辩能力：

```text
听懂机制
  +
做出正常结果
  +
定位失败
  +
完成面试表达
```

## 2. 思考题

优先使用：

- 预测题：下一步会发生什么，为什么？
- 取舍题：两个方案如何选择，前提是什么？
- 排障题：这个表象可能来自哪些层？
- 反例题：常见结论在哪些条件下不成立？

思考题应该暴露心智，不应该只是回忆定义。

## 3. ASCII 图

每课至少一张图，一图只回答一个问题。

常用图型：

```text
调用链
状态图
时序图
数据流
信任边界
失败树
对比图
```

图中标记：

- 组件和角色。
- 控制权方向。
- 关键数据或状态。
- 验证点。
- 主要失败路径。

## 4. 具体案例

使用完整案例卡：

```text
用户目标：
已有输入：
当前状态：
可用能力：
权限或资源边界：
预期输出：
真实副作用：
成功标准：
```

如果案例无法给出真实输入、状态变化或验收，它只能作为类比，不能承担主案例。

## 5. 机制与实验

### 机制推演

按真实执行顺序说明：

1. 输入如何进入系统。
2. 确定性程序做什么。
3. 非确定性决策发生在哪里。
4. 状态怎样变化。
5. 如何验证结果。
6. 何时继续、停止或恢复。

### 正常实验

记录：

```text
假设：
输入：
观察点：
程序断言或环境结果：
结论：
```

### 失败实验

至少选择一种失败：

- 输入缺失、污染或冲突。
- 参数、权限或外部执行错误。
- 状态丢失、并发冲突或重复副作用。
- 算法边界、数据偏差或评测误判。
- 超时、资源耗尽或无法停止。
- 安全攻击或供应链污染。

使用下面的排障链：

```text
表象
  ↓
候选故障层
  ↓
检查证据
  ↓
真实根因
  ↓
最小修复
  ↓
回归验证
```

## 6. 面试攻防

### 30 秒回答

```text
核心判断
+ 最小机制
+ 一个关键边界
```

### 3 分钟完整回答

```text
问题
  ↓
机制和 ASCII 图
  ↓
具体案例
  ↓
失败与取舍
  ↓
实践证据
```

### 三层追问

1. 原理：底层机制、数据结构或协议是什么？
2. 工程：失败、性能、安全和演进如何处理？
3. 项目：你实际做过什么，如何证明效果？

### 隐藏前提

识别题目没有说明的规模、数据、延迟、权限、成本和一致性要求。先明确约束，再给方案。

### 现场证据

优先准备：

- 核心代码。
- 测试和失败 Case。
- 调用日志或 Trace。
- 指标和对比实验。
- 架构图和真实产物。
- 失败复盘和重做取舍。

## 7. 验收

| 验收项 | 通过标准 |
|---|---|
| 心智 | 不看资料说清问题、机制和系统位置 |
| 图 | 独立画出数据流、状态或边界 |
| 正常实验 | 用确定证据证明机制工作 |
| 失败实验 | 定位根因并完成回归 |
| 边界 | 说明什么时候不用该机制 |
| 面试 | 完成 30 秒、3 分钟和连续追问 |
| 迁移 | 更换框架或案例后仍能识别机制 |
