# 全栈秋招高 ROI 存储体系知识总纲

## 1. 知识边界

这套总纲回答：一份业务数据从前端产生后，怎样经过缓存、操作系统、单机存储引擎和分布式系统，被读取、更新、复制、恢复和验证。

包含：

1. 浏览器持久化与 HTTP 缓存。
2. 进程内缓存和 Redis。
3. Linux 页缓存、文件系统和块设备。
4. B+Tree(B+ 树)、LSM Tree(日志结构合并树)、WAL(预写日志)、MVCC(多版本并发控制)和事务。
5. 分片、复制、共识、对象存储和纠删码。
6. 备份、恢复、数据校验、容量与成本。

不包含：

1. 某个数据库产品的完整参数手册。
2. 只与特定云厂商控制台相关的操作。
3. 数据仓库、湖仓和流处理的完整计算体系。

## 2. 数据生命周期

```text
浏览器产生数据
  ├─ 临时加速 → HTTP 缓存 / Cache API
  └─ 本地持久化 → IndexedDB
       ↓ 同步请求
应用服务
  ├─ 进程内缓存
  └─ Redis 等共享缓存
       ↓ 写入数据库
操作系统页缓存
  └─ 文件系统与块 I/O
       ↓
单机存储引擎
  ├─ WAL / Redo / Undo 保证恢复
  ├─ B+Tree 或 LSM Tree 组织数据
  └─ MVCC 与锁提供并发事务
       ↓
分布式数据层
  ├─ 分片与路由扩展容量
  ├─ 复制与共识处理故障
  └─ 对象存储与纠删码降低成本
       ↓
备份、校验、修复与容灾
```

## 4. 客户端与缓存层

### 4.1 浏览器持久化、HTTP 缓存与离线一致性

主知识点：

- localStorage(同步键值存储)、IndexedDB(浏览器事务数据库)与 Cache API(响应缓存接口)的职责边界。
- Cache-Control、ETag、条件请求和代理缓存。
- Service Worker(服务工作线程)离线读取。
- 本地数据版本、迁移、失效和多端冲突。

掌握标准：能区分“缓存响应”和“保存业务数据”，并解释强缓存、协商缓存与离线数据的一致性边界。

### 4.2 内存缓存、淘汰策略与缓存一致性

主知识点：

- Cache Aside(旁路缓存)。
- Read Through(读取穿透)与 Write Through(写入穿透)。
- Write Back(延迟回写)。
- LRU、LFU、TTL 与容量淘汰。
- 缓存穿透、击穿、雪崩和热点 Key。
- 双删、订阅失效、版本号与最终一致。

依赖关系：

```text
重复读取
  └─ 引入缓存降低延迟
       ├─ 容量有限 → 淘汰策略
       ├─ 数据会更新 → 一致性策略
       ├─ 热点集中 → 隔离与限流
       └─ 缓存失效 → 回源保护
```

掌握标准：能根据读写比、容忍陈旧时间和故障模式选择缓存策略。

## 5. 操作系统与持久化边界

### 5.1 页缓存、文件系统与 fsync 持久化语义

主知识点：

- 用户缓冲、运行时缓冲和内核页缓存。
- write 系统调用、脏页和后台回写。
- 文件系统元数据、日志和原子重命名。
- fsync、fdatasync、目录同步与崩溃窗口。
- 块层、设备缓存和稳定介质确认。

依赖关系：

```text
应用返回“写入成功”
  └─ 可能只进入用户缓冲或页缓存
       ↓
文件系统安排数据和元数据
  └─ fsync 建立应用可要求的持久化边界
       ↓
设备完成稳定写入
```

掌握标准：能解释 write 返回、close、fsync 和数据库提交为何不等价，并设计断电窗口实验。

### 5.2 SSD、写放大与尾延迟

主知识点：

- 页、块、擦除和 Flash Translation Layer(闪存转换层)。
- 顺序写、随机写和垃圾回收。
- 设备级与存储引擎级写放大。
- 队列深度、吞吐、平均延迟和尾延迟。

掌握标准：能解释 LSM Compaction、文件系统和 SSD 垃圾回收如何叠加产生抖动。

## 6. 单机存储引擎

### 6.1 B+Tree 页组织、索引与范围查询

主知识点：

- 页、记录、槽和扇出。
- 聚簇索引、二级索引与回表。
- 页分裂、页合并和填充因子。
- 联合索引、最左前缀和覆盖索引。

掌握标准：能从查询条件推导索引访问路径，并解释高扇出为何减少 I/O。

### 6.2 WAL、Redo、Undo 与崩溃恢复

主知识点：

- Write-Ahead Logging(预写日志)约束。
- Redo 重做、Undo 撤销和事务状态。
- 日志序列号、检查点和恢复扫描。
- Group Commit(组提交)与持久化批处理。

依赖关系：

```text
随机更新数据页成本高
  └─ 先顺序追加 WAL
       ├─ 提交前保证日志持久 → 崩溃后可 Redo
       ├─ 保存旧版本或反向操作 → 可 Undo
       └─ 检查点缩短恢复范围
```

掌握标准：能画出事务提交、脏页回写和崩溃恢复的先后关系。

### 6.3 MVCC、锁与事务隔离

主知识点：

- 原子性、一致性、隔离性和持久性。
- 版本链、快照和可见性判断。
- 行锁、间隙锁、谓词冲突和死锁。
- Read Committed(读已提交)。
- Repeatable Read(可重复读)。
- Serializable(串行化)。
- 脏读、不可重复读、幻读和写偏差。

掌握标准：能用两个并发事务推导可见版本、锁等待和异常，并说明隔离级别的代价。

### 6.4 LSM Tree、SSTable、Compaction 与 Bloom Filter

主知识点：

- MemTable、WAL 和不可变 SSTable。
- Leveling 与 Tiering Compaction。
- 读放大、写放大和空间放大。
- Bloom Filter(布隆过滤器)、索引块和块缓存。
- Tombstone(墓碑记录)与范围删除。

掌握标准：能解释写优化如何转移成后台合并和读放大，并根据负载选择 B+Tree 或 LSM。

## 7. Redis 与共享缓存

### 7.1 Redis 持久化、复制与故障切换

主知识点：

- RDB 快照、AOF 追加日志和重写。
- 主从复制、复制偏移与部分重同步。
- 异步复制的数据丢失窗口。
- Sentinel 监控、选主与客户端重连。
- Cluster 分片、槽位和故障切换边界。

依赖关系：

```text
内存数据低延迟
  └─ 进程退出会丢失
       ├─ RDB 提供时间点快照
       └─ AOF 记录写命令
            ↓
单机仍会失效
  └─ 主从复制提供副本
       ↓
主节点故障
  └─ Sentinel 或 Cluster 完成选主与路由更新
```

掌握标准：能根据恢复时间目标和可接受数据丢失窗口选择策略，并说明切换不等于零丢失。

## 8. 分布式数据层

### 8.1 分片、热点、重平衡与路由

主知识点：

- 范围分片、哈希分片和一致性哈希。
- 分片键、热点和跨分片查询。
- 元数据路由、迁移和双写窗口。
- 在线重平衡、限速和回滚。

掌握标准：能识别坏分片键，并设计不丢写的迁移状态机。

### 8.2 复制、Quorum 与一致性模型

主知识点：

- 单主、多主和无主复制。
- 同步、异步和半同步复制。
- Quorum 读写、版本冲突和读修复。
- 线性一致、顺序一致、会话一致和最终一致。

掌握标准：能先声明故障模型，再解释读写成功条件和可能观察到的旧值。

### 8.3 共识日志、Leader 切换与线性一致性

主知识点：

- Leader、任期、日志复制和提交索引。
- 多数派确认与已提交日志。
- 选举、脑裂防护和旧 Leader 隔离。
- 线性化点、租约读和 Read Index。

掌握标准：能解释复制与共识的差异，以及为什么多数副本存有日志仍不一定已经提交。

### 8.4 对象存储、数据放置与纠删码

主知识点：

- 对象、Bucket、Key 和不可变大对象。
- 元数据与数据分离。
- 一致性哈希、CRUSH 等确定性放置。
- 多副本与纠删码的容量、网络和修复取舍。
- 分段上传、版本控制和生命周期。

掌握标准：能为图片、视频和备份选择对象存储，并解释纠删码为何节省空间但增加修复计算与网络。

## 9. 数据保护与运行治理

### 9.1 快照、备份、PITR 与容灾

主知识点：

- 逻辑备份、物理备份和快照。
- 全量、增量和日志归档。
- Point-in-Time Recovery(时间点恢复)。
- RPO、RTO、同城和异地容灾。
- 恢复演练和备份不可变性。

掌握标准：能从业务目标反推备份频率、日志保留和恢复流程。

### 9.2 数据校验、后台修复与静默损坏

主知识点：

- Checksum(校验和)、端到端校验和版本号。
- Scrubbing(后台巡检)、副本比较和修复。
- Bit Rot(静默位腐化)与错误传播。
- 幂等修复和审计记录。

掌握标准：能解释“副本都在线”为什么仍不能证明数据正确。

### 9.3 容量规划、可观测性与成本分层

主知识点：

- 容量、吞吐、IOPS、延迟分位数和队列。
- 命中率、写放大、压缩积压和恢复时间。
- 热、温、冷数据分层。
- 保留策略、生命周期和单位成本。

掌握标准：能从增长率和故障余量推导容量，并使用尾延迟和积压而非平均值判断风险。

## 10. 完整依赖图

```text
客户端存储与 HTTP 缓存
  └─ 解决本地读取和离线问题
       ↓
进程内缓存与 Redis
  └─ 解决跨请求低延迟访问
       ↓
页缓存、文件系统与 fsync
  └─ 定义内存到稳定介质的边界
       ↓
单机存储引擎
  ├─ B+Tree / LSM 组织数据
  ├─ WAL / Redo / Undo 处理崩溃
  └─ MVCC / 锁处理并发事务
       ↓
分布式数据层
  ├─ 分片扩展容量
  ├─ 复制与共识处理节点故障
  └─ 对象存储与纠删码优化大对象成本
       ↓
备份、校验、修复、容量与成本
  └─ 处理系统性故障和长期运行
```

阅读顺序：从一次写入在单机上的持久化边界开始，再学习索引和事务，最后扩展到多副本和容灾。浏览器与缓存层用于把全栈入口接到同一条数据生命周期。

## 11. 掌握标准

| 层级 | 证据 |
|---|---|
| 已理解 | 能画出一次读写经过的缓冲、日志、索引和副本 |
| 已实验 | 能注入进程崩溃、节点故障或缓存失效并记录结果 |
| 已整合 | 能在真实项目中定义持久化、一致性和恢复目标 |
| 已复核 | 更换 MySQL、PostgreSQL、Redis、RocksDB 或对象存储后仍能推导 |
