## 核心推导链

```text
无序数组
  ↓ 查找和更新代价高
二叉搜索树维护有序不变量
  ↓ 插入顺序可能让树退化
平衡树限制高度
  ↓ 只关心最值时维护完整有序仍然浪费
堆维护局部顺序
  ↓ 查询模式继续分化
Trie / 区间树 / 并查集等索引型结构
```

## 阶段一：二叉搜索树有序不变量

### 本阶段知识点群

| 知识点 | 作用 | 前后关系 |
|---|---|---|
| 二叉搜索树 | 左子树键小、右子树键大 | 把线性扫描变为沿路径查找 |
| 中序遍历 | 按键输出有序序列 | 验证有序不变量 |
| 删除替代节点 | 保持删除后的排序关系 | 暴露结构高度问题 |

### 当前问题

无序数组按 ID 查询需要扫描全部选手；每次更新后重新排序又会让写入成本过高。

### 推导过程

V0 的数组没有利用键的顺序。V1 引入二叉搜索树，把每次比较的结果转化为“只进入左侧或右侧子树”。查询、插入和删除都只沿一条根到节点的路径推进。

### 机制全解

二叉搜索树的核心不是“长得像树”，而是全局有序不变量：任一节点左子树所有键小于该节点，右子树所有键大于该节点。查找根据比较结果排除一半方向，中序遍历得到有序结果。

删除叶子可以直接移除；只有一个孩子时由孩子接管位置；两个孩子时通常选择后继或前驱替代，再删除被移动节点。所有操作成本取决于树高`h`，不是天然等于`log n`。

### 状态变化

| 维度 | 无序数组 | 二叉搜索树 |
|---|---|---|
| 输入 | ID 和记录 | ID、记录和比较关系 |
| 不变量 | 无 | 左小右大 |
| 控制过程 | 全量扫描 | 沿比较路径下降 |
| 输出 | O(n) 查找 | O(h) 查找与更新 |
| 仍未解决 | 查询慢 | h 可能退化到 n |

### 阶段结论

二叉搜索树用有序不变量缩小搜索空间，但性能完全依赖结构高度。

## 阶段二：平衡树高度约束

### 本阶段知识点群

| 知识点 | 作用 | 前后关系 |
|---|---|---|
| 平衡树 | 对高度或颜色增加约束 | 稳定最坏查询路径 |
| 旋转 | 局部改变父子关系 | 恢复平衡且保持中序顺序 |
| AVL 与红黑树 | 在查询和更新成本间取舍 | 提供不同工程平衡点 |

### 当前问题

排行榜分数可能近似递增，普通搜索树会形成单支链，查询重新退化为 O(n)。

### 推导过程

V1 只维护有序。V2 再增加结构约束：每次插入或删除后检查高度或颜色性质，使用旋转把过深子树提升。旋转改变局部形状，却不改变中序序列。

### 机制全解

AVL 树严格限制左右子树高度差，因此查找路径更短，但更新后可能需要更多再平衡。红黑树通过颜色和黑高性质给出较宽松的平衡，树高仍保持 O(log n)，通常更适合更新频繁的通用有序容器。

左旋和右旋的关键是保持键的相对顺序。旋转不是任意交换节点，而是让某个孩子接管根位置，并重新连接中间子树。平衡信息是额外状态，更新操作必须同步维护。

### 状态变化

| 维度 | 普通搜索树 | 平衡树 |
|---|---|---|
| 输入 | 键和记录 | 键、记录和平衡元数据 |
| 不变量 | 左小右大 | 有序 + 高度或颜色约束 |
| 控制过程 | 插入后结束 | 插入后沿祖先恢复平衡 |
| 输出 | 平均可能较快 | 最坏 O(log n) |
| 仍未解决 | 高度退化 | Top K 只需最值，却维护了完整顺序 |

### 阶段结论

平衡树用更新时的旋转成本换取稳定查找上界，适合动态有序映射，但不是所有查询的最低成本结构。

## 阶段三：堆与优先队列局部顺序

### 本阶段知识点群

| 知识点 | 作用 | 前后关系 |
|---|---|---|
| 堆 | 只保证父子最值关系 | 用更弱不变量降低维护成本 |
| 上浮与下沉 | 插入、删除堆顶后恢复不变量 | 保持 O(log n) 更新 |
| 优先队列 | 按优先级弹出任务或候选 | 支撑 Top K 和调度 |

### 当前问题

维护 Top 100 时，系统只关心当前集合中的最小分数，平衡树却维护了任意两个元素的完整排序。

### 推导过程

V2 拥有完整有序映射。V3 为 Top K 单独维护大小为 100 的小顶堆：新分数不高于堆顶就忽略，高于堆顶则替换并下沉。系统只维护“父节点不大于孩子”的局部不变量。

### 机制全解

二叉堆通常用数组表示完全二叉树，因此父子索引可由算术计算。小顶堆只保证任一父节点不大于孩子，根是全局最小值，但左右子树之间没有完整顺序。

插入先放在数组末尾，再不断上浮；删除堆顶时用末尾元素替换根，再向下选择更合适的孩子交换。建堆可以自底向上下沉，整体 O(n)。堆适合最值和优先级，不适合按任意键查找或范围遍历。

### 状态变化

| 维度 | 平衡树 | Top K 小顶堆 |
|---|---|---|
| 输入 | 全部选手分数 | 候选分数和 K |
| 不变量 | 完整有序 + 平衡 | 父节点不大于孩子 |
| 控制过程 | 每次维护全序 | 只比较堆顶并局部修复 |
| 输出 | 任意键和范围有序 | O(1) 取得当前门槛 |
| 仍未解决 | 维护成本较高 | 不支持昵称前缀和定制查询 |

### 阶段结论

堆通过弱化不变量换取更低的目标查询成本。数据结构选择本质上是“为哪些查询预先维护哪些关系”。

## 阶段四：索引型树结构与查询形状

### 本阶段知识点群

| 知识点 | 作用 | 前后关系 |
|---|---|---|
| Trie | 按字符前缀共享路径 | 解决昵称前缀检索 |
| 区间树与树状数组 | 保存区间聚合信息 | 解决动态范围统计 |
| 并查集 | 维护集合代表与合并关系 | 解决动态连通性 |

### 当前问题

按 ID 和分数建立的索引无法高效回答昵称前缀，也不能直接处理动态区间统计或集合连通性。

### 推导过程

V3 已经承认不同查询需要不同不变量。V4 按查询形状建立索引：Trie 让相同前缀共享路径，区间结构在节点保存聚合值，并查集只保存父指针和集合代表。

### 机制全解

Trie 的路径对应字符序列，查询复杂度主要与字符串长度相关，但节点数量和字符集会增加空间成本。树状数组和线段树把区间拆成可组合节点，适合更新与查询交替出现的统计。

并查集通过`find`寻找集合代表，通过`union`合并集合；路径压缩和按秩合并让摊还成本接近常数。它擅长“是否连通”，但不保存完整路径和边权。

### 状态变化

| 维度 | 通用树与堆 | 查询定制索引 |
|---|---|---|
| 输入 | 比较键或优先级 | 前缀、区间或集合关系 |
| 不变量 | 有序或父子最值 | 路径共享、聚合值或集合代表 |
| 控制过程 | 通用比较 | 按查询结构导航 |
| 输出 | 查找或最值 | 前缀、区间或连通性结果 |
| 仍未解决 | 查询类型有限 | 多索引的一致性和空间成本 |

### 阶段结论

不存在脱离查询模式的“最优数据结构”。工程选择应从需要稳定回答的查询和更新出发，再定义最小不变量。

## 正常链路与失败链路

```text
正常：
查询目标 → 选择最小必要不变量 → 更新时恢复不变量 → 查询命中

失败：
只看平均复杂度 / 忽略退化输入 / 用堆做任意查找
  → 不变量与查询不匹配 → 延迟或实现复杂度失控
```

## 实验任务卡

### 实验任务一：让二叉搜索树退化并恢复

实验目标：验证操作复杂度由树高决定，并观察平衡约束的作用。

覆盖知识点：二叉搜索树、平衡树。

准备条件：实现普通 BST 和一个可用的平衡树容器，或使用语言标准库有序映射作为对照。

操作步骤：

```text
1. 依次插入 1 到 10000。
2. 记录普通 BST 的最大深度和查询比较次数。
3. 随机打乱相同键再插入并比较。
4. 使用平衡树重复测试。
```

预期现象：递增输入让普通 BST 接近链表，随机输入改善平均高度；平衡树在两类输入下高度均为对数级。

通过标准：能用实际高度解释耗时差异，并证明中序遍历仍有序。

产出证据：高度、比较次数、耗时和中序校验结果。

### 实验任务二：Top K 的全排序与小顶堆对照

实验目标：验证弱化不变量能降低只取 Top K 的维护成本。

覆盖知识点：堆与优先队列、索引型树结构。

准备条件：生成一百万个随机分数，设置 K=100。

操作步骤：

```text
1. 全量排序后取前 100。
2. 使用大小为 100 的小顶堆流式处理。
3. 对比峰值内存、比较次数和耗时。
4. 尝试用堆按选手 ID 查询，记录为何不合适。
```

预期现象：小顶堆只维护 K 个候选，空间和维护成本更低；按任意 ID 查找仍需扫描。

通过标准：Top K 结果一致，并能说明堆的能力边界。

产出证据：结果哈希、耗时、峰值内存和查询能力表。

## 自测题与答案

### 题目一

为什么普通二叉搜索树的查询复杂度是 O(h)，而不是固定 O(log n)？

参考答案：每次查询沿根到目标节点的路径下降，路径长度由树高 h 决定；只有树高受控时才是 O(log n)，退化链表时为 O(n)。

判分点：指出复杂度变量是树高，并给出递增插入反例。

常见误区：看到“二叉”就认为每次一定排除一半节点。

### 题目二

堆为什么适合 Top K，却不适合范围查询？

参考答案：堆只维护父子最值关系，能快速取得堆顶并局部修复，但兄弟和不同子树之间没有完整顺序，无法沿有序边界做范围遍历。

判分点：说出局部不变量和查询能力之间的关系。

常见误区：把堆的数组表示误认为数组整体有序。

### 题目三

选择数据结构时最先问什么？

参考答案：先明确需要稳定支持的查询、更新、顺序和空间约束，再选择最小必要不变量。

判分点：至少覆盖查询模式、更新模式和退化边界。

常见误区：根据熟悉程度或平均复杂度表直接选择。

## 知识关系图

```text
[二叉搜索树]
  └─ 用全序支持动态查找 → [平衡树]
                               └─ 限制高度稳定最坏复杂度

[堆]
  └─ 弱化为父子最值关系 → [优先队列 / Top K]

[查询形状]
  ├─ 前缀 → [Trie]
  ├─ 区间 → [区间树结构]
  └─ 连通 → [并查集]
```

### 如何读图

先看查询需要什么关系，再看对应结构维护了多强的不变量。维护关系越强，查询能力通常越多，但更新、空间和实现成本也越高。
